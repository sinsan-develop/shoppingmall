# 어울몰 정산 설계변경 구현 계획 / Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: 구현 지시를 받은 뒤 `superpowers:subagent-driven-development` 또는 `superpowers:executing-plans`를 사용한다. 아래 `- [ ]`는 실제 실행·증거 확인 전에는 체크하지 않는다.

**Goal:** [설계서](design/DESIGN.md) v1.2 R09의 A1 정정 계약을 현재 `main` 코드에서 검증·보호하고, A2 과거 판매자 분류별 완료 이력을 개발하며, A3의 분리된 검증 경계로 실증한다.

**Architecture:** 기존 `settlement_events` 불변 장부와 완료 사건 연결을 재사용한다. A1 정정은 PR #16으로 병합된 0022/API/화면을 기준선으로 삼고 다시 만들지 않는다. A2는 완료 시점 분류 스냅샷과 연결 사건의 당시 분류를 합쳐 읽기·인쇄 계약을 확장하며, 공유 DB 변경은 별도 승인 뒤 적용한다.

**Tech Stack:** NestJS·TypeScript, PostgreSQL 15/Drizzle migration, Next.js/React 관리자·판매자 화면, Node 시험, Chromium 인쇄/PDF. 개발 원격은 `git@github-sinsan-develop:sinsan-develop/shoppingmall.git`만 사용한다.

**Spec:** `D:/Project/shoppingmall2/docs/design/DESIGN.md` v1.2 R09·4·6·7절 및 `D:/Project/shoppingmall2/docs/design_change.md`. 기존 0020·0021 근거는 `docs/S6_SETTLEMENT_CONTRACT_PROPOSAL.md`와 `docs/S6_COMPLETED_AMOUNT_DESIGN_PROPOSAL.md`다. 파일명 `WORK_PLAN_20260-10-09.md`는 신산님 지정 그대로 유지한다.

## Global Constraints — 공통 제약과 판정

- 이번 지시는 **계획 작성만** 수행한다. 구현·공유 DB 적용·PR·배포는 이 문서 작성으로 승인된 것으로 보지 않는다. `docs/WORK_PLAN.md`와 지정 설계서를 이 계획 작성 과정에서 수정하지 않는다.
- `docs/design_change.md`는 A1·A2 제품 계약과 A3 검증 경계의 권고안이 승인됐다고 기록한다. 2026-10-10 실제 `main@399f77b`에는 PR #16의 C1/C1.2·0022 소스만 있고, C2·0023 소스는 없다. 과거 계획의 ‘A1~A3 미승인’, ‘C1 미병합’ 문장은 현재 판정에 사용하지 않는다. 공유 DB의 0022 적용 여부·행 수는 작업 직전에 재조회해야 한다.
- 어울몰 자체 판매자는 다른 판매자와 같은 판매자 단위다. 관리자만 정산 완료·수수료 입력을 한다. 자동 송금, 부담 주체·최종 지급액 자동 결정은 제외한다.
- 기존 0020·0021·0022 migration과 C1/C1.2의 불변 장부·정정·완료 사건 연결·`lateGroups`/`lateTotals`·`frozenTotals`를 다시 구현하지 않는다. 기존 결제·환불 사건의 발생 시점과 원주문 연결을 보존한다.
- 신산님 선택에 따라 공유 `WSL-server`의 `local-postgres/shoppingmall`에는 불변 가상 정산 거래 행을 남기지 않는다. 공유 DB 행 E2E는 현재 **미검증**이며 격리 DB 통과로 바꿔 쓰지 않는다.
- 실제 발송·수신, PG 실거래, Oracle 배포, 사용자 인수테스트는 이번 개발 완료 대상 밖이다. 시험 계정·격리 자료만 사용하고 Secret/실계좌를 기록하지 않는다.
- 구현 시 로컬 `main`에서 직접 개발·커밋하지 않는다. 현재 `codex/next-work-20261010`이 `main@399f77b`에서 만들어진 로컬 브랜치이나, 구현 시작 전 최신 `origin/main`·dirty/untracked·원격 브랜치를 다시 확인한다. 사용자 소유 미추적 문서를 일괄 stage하지 않는다. 작업자의 격리 경로는 사용자 산출물 경로가 아니며, 신산님 지정 계획서·설계서 경로를 대체하지 않는다.
- 실제 완료 증거는 변경 SHA, 시험 명령·통과/실패/건너뜀, 정확한 DB/브라우저 환경과 임시 자료 정리, 독립 리뷰, PR·병합 후 smoke를 분리해 `WORK_STATUS.md`에 기록한다. 기록상 진도 완료와 기능·검증 PASS는 다르다.
