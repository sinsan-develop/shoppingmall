# 어울몰 개발·인수 범위 보완안

- 상태: **신산님 검토 대기**. 2026-09-27까지의 직접 결정과 기존 [제품 설계 1.0](DESIGN.md)을 연결한 구현 계약 초안이다. 이 문서만으로 DB·인증·비용·배포·출시를 승인하지 않는다.
- 우선순위: 신산님의 최신 직접 지시 → 별도 승인된 본 보완안 → DESIGN 1.0 → PRD·기술 방향 → 과거 시안·참고 저장소. 문서 간 충돌은 작업을 멈춰 범위와 선택지를 보고하고 확정한다.
- 연결 문서: [개발 작업계획](../WORK_PLAN.md), [배포·사용자 인수 계획](../DEPLOYMENT_UAT_PLAN.md), [작업현황](../../WORK_STATUS.md).

## 1. 변하지 않는 거래 규칙

1. 제품명은 **어울몰**이다. 만석 자료의 황금·크림·먹빛, 서체·카드 요소는 시각 참고이며 지역 이야기는 대외 콘셉트일 뿐 상품 산지·판매자 등록의 시스템 제한이 아니다. 균형형 Flat v2를 제품의 시각 기준으로 채택하되, 현재 별도 branch의 정적 시안은 실제 브라우저·반응형·인쇄·키보드 검증과 통합이 아직 끝나지 않았다.
2. 역할은 고객·판매자·관리자. 농가와 어울몰 자체 판매자는 **동일한 판매자 역할**이다. 같은 사람이 판매자이자 관리자일 수 있으나 권한·화면 행위·감사 이력을 분리한다. 정산 완료 주체와 환불 결정·집행 주체는 관리자다. 판매자는 자기 소속의 상품·주문·재고만 처리한다.
3. 상품 분류는 `대분류 → 소분류 → 상품`, 판매자 분류는 별개의 `판매자 분류 → 판매자`이다. 관리자가 분류와 판매자를 만들고, 판매자는 기존 소분류에 자기 상품의 신규·수정·판매중지 요청을 제출한다. 공개 변경은 관리자 승인 뒤 반영한다. 실제 삭제는 거래·감사 이력 보존과 충돌하므로 판매중지/비공개를 기본 제안하며 물리 삭제는 별도 보존정책 승인 전 금지한다.
4. 재고 0·품절의 구매 차단은 즉시; 재고 증가·재판매는 관리자 승인 뒤. 판매자는 재고 수량을 직접 입력한다. 가격×고객 선택 수량이 상품 금액이며 장바구니에서 수량 변경·제거가 가능해야 한다.
5. 장바구니에는 모든 판매자 상품을 함께 담을 수 있다. 결제 시 어울몰 발송과 판매자 직접 발송, 직접 발송 판매자별로 **발송 주문을 분리**하고 하나의 통합 결제로 지불한다. 한 발송 주문 안에는 발송 방식이나 직접 발송 판매자를 섞지 않는다.
6. 기본 배송비는 발송 주문마다 3,000원, 무료배송 기준은 각 발송 주문의 **할인 전 상품 소계 50,000원 이상**이다. 판매자별 배송비·무료배송 기준 변경은 요청→관리자 승인 뒤 적용. 출고 전 적법한 발송 주문 전체 취소는 실제 결제한 상품 금액과 배송비를 환불한다. 출고 후 교환·환불/배송·반송비는 변경 가능한 **시험 정책**으로 검증하되, 법률 검토·고객 약관 확정 전 운영 기본 정책으로 간주하지 않는다.
7. 정산은 매출·수수료·배송비·할인·환불을 **각 사건 발생일**에 기록하고 원주문·상품 근거를 연결한다. 전체/판매자 분류/개별 판매자 필터와 임의 기간 조회·판매자별 구획·소계·전체 요약, 브라우저 인쇄→PDF 저장을 제공한다. 어울몰 자체 판매자도 동일한 한 판매자로 조회한다. 기간별 완료는 관리자만 **판매자별 개별** 표시한다. 이미 완료한 5월의 판매를 7월 환불 때문에 소급 변경하지 않고 7월에 환불 사건을 기록한다. 최종 지급액의 자동 가감·비용 부담 판정·자동 송금은 현 범위 밖이다.

## 2. 이번 제품에 포함할 화면·기능

| 영역 | 개발·인수 포함 | 의도적으로 후속 |
|---|---|---|
| 홈·탐색 | 큰 상품 검색, 어울몰 자체 메뉴, 이벤트/기획전 카드, 상품 대분류 바로가기, 모두에게 같은 관리자 편집 추천 목록. 검색은 승인·판매 가능 상태만 대상으로 하며 상품 분류와 전시 메뉴는 별개다 | 개인별 추천, 광고 타기팅/집행, 라이브·다른 쇼핑몰 서비스명 복제, 자동 동의 없는 행동 추적 |
| 상품·판매자 | 분류·판매자 등록, 승인 흐름, 이미지 다중 업로드와 대표/상세 구분·미리보기, 옵션/상세 설명, 판매자별 주문 상태·클레임 응대, 관리자 최종 처리 | 외부 판매자 자율 입점과 공개 변경 자동 승인 |
| 프로모션 | 관리자가 등록·수정·중지하는 쿠폰/상품·주문 할인, 발송 주문별 배송비 지원, 전시 배너. 실제 견적·PG 시험 결제·환불·정산 발생 자료에 연결 | 광고 과금, 포인트·등급, 복잡한 캠페인 자동 최적화 |
| 운영 | 주문·결제·재고·배송·클레임 예외 조회와 감사 이력. 자세한 KPI·자동 경보/운영 제어 범위는 아래 미결정 게이트 | 근거 없는 SLA 달성 선언, 기본 PIN `0000`, 무승인 운영 잠금·강제정지 |
| 배송·알림 | 판매자 운송장·상태 입력과 고객 조회, 시험 계정 문자·메일·Android 푸시 실제 수신. 에뮬레이터 반복 시험 후 연결된 실기기에서 최종 수신 확인 | 택배사 API 자동 상태 동기화, 알림톡·iOS 푸시의 이번 인수 필수화 |
| 결제·앱 | 시험 PG에서 카드 승인·부분 환불·실패/중복 처리; **빌드 전 어울몰 앱 아이콘 시안 제작·승인**, 웹·Android 에뮬레이터 및 연결된 실기기의 설치·카카오 로그인·결제 복귀 | 인수 중 실금액 결제, 가상계좌·간편결제 확대, iPhone 실기기·Apple 로그인 실검증 |

### 프로모션 금액 규칙 — 확정 부분과 상세 승인 필요 부분

- 확정: 통합 결제당 할인 쿠폰은 최대 1개, 발송 주문별 배송비 지원은 최대 1개. 두 종류는 함께 적용할 수 있다. 배송비 면제 판단은 할인 **전** 발송 주문 상품 소계로 먼저 결정한다. 이미 무료배송인 주문에 지원액을 중복 현금성 할인으로 바꾸지 않는다.
- 상세 계약 승인 전 제안: 할인 적용 대상 SKU/판매자/기간·최소구매금액, 정액/정률 상한, 쿠폰 총발행·사용 횟수, 동시 주문 경쟁, 취소 시 쿠폰 반환과 할인 배분·반올림, 관리자 중지 후 이미 확정된 주문의 금액 불변, 배송비 지원의 실제 배송비 이하 한도를 S3 착수 전 사례 표로 승인받는다. 이 값이 없으면 임의로 운영 혜택을 발행하지 않고 가상 고정 fixture만 사용한다.
- 시험 정책값과 운영 예산·회계 부담 주체는 별개다. 정산 장부는 할인과 배송비 지원 **발생 금액**을 보존하지만 농가/어울몰 최종 지급액을 자동 결정하지 않는다.

## 3. 권한·데이터 계약 설계 시 반드시 다룰 항목

- 관리자의 분류/판매자/프로모션·정책 작성 권한과 판매자 요청 권한을 서버에서 검사한다. 관리자 우선 정책과 판매자별 승인된 오버라이드, 적용 시각, 승인자/요청자, 기존 주문의 정책 스냅샷을 분리한다.
- 주문·결제·환불·정산은 원화 정수, 통합 결제 ID와 발송 주문 ID를 별도로 추적한다. 할인·배송비 배분의 원 단위 합을 맞추고 취소·콜백 중복/역순을 멱등 처리한다. 승인 전 공개 버전과 승인 대기 초안을 분리한다.
- 판매자 분류의 재배치나 이름 변경이 과거 거래·정산의 당시 판매자 소속을 바꾸지 않도록 식별자와 사건 시점의 근거를 보존한다. 삭제/보존기간, 고객 탈퇴/증빙/이미지 접근권한, 개인정보 마스킹은 승인된 schema·법률 검토에 따라 결정한다.
- 운영 지표 후보(`주문 생성 실패율 <0.5%`, `결제 승인 지연 p95 <3초`, `배송 갱신 <5분`, `페이지 p95 <2.5초`)는 **정의·측정 전 목표 후보**이지 인수 합격 보증이 아니다. 특히 택배사 자동 동기화가 없는 동안 외부 배송사 상태 5분 갱신을 약속하지 않는다.

## 4. 선행 검토와 남은 선택

1. 관리 관제의 이번 인수 필수 범위: **신산님 답변 대기**. 기본 제안은 주문·매출·재고·클레임 요약 및 실패 결제·미출고 등 처리 목록, 자동 외부 경보/점검 스위치/판매자 강제 정지는 후속이다. 답변에 맞춰 작업계획 Stage·시험 사례를 수정한다.
2. 이 보완안은 기존 분류·홈 서면 초안의 직접 지시 사항을 모으지만 해당 시안의 모든 세부를 자동 승인한 것으로 주장하지 않는다. Flat v2 branch를 정본에 합치기 전 브라우저 QA·PR 검증과 충돌 대조가 필요하다.
3. 신산님 확인 기준 외부 계정 현황: **PG 시험상점 없음**, **카카오 개발자 앱은 사용 가능**(기존 앱 존재·소유·권한 확인 전), **문자·메일 발송 서비스 준비됨**(실발송 권한·설정 확인 전), **Expo·Firebase 모름**. Android 에뮬레이터 화면과 연결된 실기기가 있다고 신산님이 추가로 알렸으나 실제 앱/푸시 시험은 아직 없다. 각 항목을 인수 준비 체크리스트에서 소유자·권한·비용·시험 수신 대상으로 확인한다. Secret 값은 문서·Git·대화에 남기지 않는다.
4. Oracle Cloud 계정·서버가 있다고 신산님이 확인했지만 실제 서버 식별·기존 서비스·격리·백업·복구·비용·접속 경로는 검증 전이다. 별도 [배포·인수 계획](../DEPLOYMENT_UAT_PLAN.md)의 게이트에서 결정한다. 인수 합격은 법률 검토, PG 운영 계약, 실판매 자료/정책, iOS/Apple과 공개 출시 승인이 아니다.
5. Android 앱 아이콘은 기존 만석 로고를 그대로 바꾸어 쓰지 않는다. 어울몰 전용 마크의 축소 가독성·명암·원형/둥근 마스크·적응형 아이콘 전경/배경을 Flat v2 시각 기준으로 제안해 신산님 검토를 받는다. 아이콘 제작·승인은 빌드/배포 직전에 미루지 않고 S7 구현 전 별도 작업으로 배치한다.
