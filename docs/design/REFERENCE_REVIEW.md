- 역할별 진입 경로 `/buyer`, `/seller`, `/operator`는 기존 시안의 예시일 뿐이다. 새 제품의 확정 URL이나 기존 정적 HTML을 그대로 재사용한다는 뜻이 아니다.
- 기능별 메뉴 분리, 상품 이미지·옵션 편집·미리보기, 재고·주문 상태별 조회, 지연·품절 등 운영 예외 표시는 선택 가능한 참고 아이디어다. 현행 설계와 충돌하면 채택하지 않는다.
- 기존 설계서·작업계획서에서 현행 PRD에 보완한 것은 다중 상품 사진의 대표·순서·미리보기, 주문·클레임 상태와 사유 이력, 담당자가 확인할 운영 예외 목록, 권한·입력·업로드 보안 및 복원·복귀 검증 기준이다. 이 항목도 현행 판매자 요청→관리자 승인과 관리자 환불·정산 권한을 따른다.
- 원격에 이미 있는 정적 화면은 디자인 참고 자료다. A/B/C 테마는 로컬 미커밋 추가안이므로 원격 확정안이나 최종 브랜드로 간주하지 않는다. 로고·색상 역시 신산님 검토 전까지 최종 확정하지 않는다. 현행 설계에 맞춘 정적·클릭형 시안의 검토·승인 순서는 PMO 제품 디자인 표준을 따른다.

## 4. 설계·검증에 반영할 시나리오

1. 일반 사용자가 서로 다른 농가의 상품과 어울몰 발송 상품을 한 장바구니에 담으면, 농가별·발송 방식별 주문으로 나누되 한 번에 결제한다.
2. 무료배송 5만 원 조건은 각 발송 주문의 할인 적용 전 상품금액으로 판정하고, 기준 미달 발송 주문에는 배송비 3,000원을 표시한다.
3. 농가와 어울몰은 같은 판매자 역할·처리 절차를 사용하며 담당 상품·주문 범위만 구분한다. 관리자 설정이 충돌 시 우선한다. 판매자의 일반 제안은 관리자 승인 후에만 고객 화면에 반영하되, 재고 0개·품절 시 구매 차단과 실제 출고·운송장은 즉시 반영한다. 담당 범위의 기본 배송비·무료배송 기준 변경도 승인 절차를 따른다. 판매자와 관리자는 실제 동일인이어도 별도 역할이고, 동일인이 두 권한으로 각각 요청·승인을 수행하면 이력을 분리한다.
4. 고객 환불은 전체 관리자가 결정·처리한다. 한 발송 주문을 출고 전에 적법하게 취소하면 그 주문의 상품금액과 실제 결제 배송비를 환불하고, 같은 통합 결제의 다른 발송 주문은 유지한다. 출고 후 환불의 배송비·반송비 부담은 사유별 법률·약관 검토 전 확정하지 않는다.
5. 관리자가 시작일·종료일을 선택해 농가별 정산 자료를 확인하고 농가마다 완료를 개별 표시한다. 한 농가의 완료가 다른 농가의 상태를 바꾸지 않는다. 5월 1일 판매·5월 20일 정산 완료·7월 1일 환불이면 7월 1일 환불 사건으로 기록하고 5월 1일 주문·상품을 근거로 연결한다. 완료된 과거 기간은 소급 변경하지 않는다.
6. 동일 농가의 완료된 정산 기간과 겹치는 새 기간은 중복 완료를 막는다. 어울몰 발송 농가 생산품은 어울몰의 출고·재고 담당과 별도로 생산 농가의 정산 근거를 유지한다.
7. 통합 결제 할인은 대상 상품의 할인 전 금액에 비례해 발송 주문에 배분하고 배분 합계가 실제 할인액과 일치한다. 출고 전 한 발송 주문의 일부 상품을 취소해 무료배송 기준 아래로 내려가도 남은 주문에 배송비를 새로 부과하지 않는다.
8. 판매자의 재고 증가·품절 해제는 관리자 승인 후 적용한다. 출고 마감시간 이후 주문은 다음 출고 가능일을 안내하고, 출고·운송장 입력 오류는 관리자가 이력을 남겨 정정하며 고객 안내도 바로잡는다.

## 5. 설계에서 아직 확인할 것

- 현행 설계에 맞춘 새 시안의 정보구조·시각 스타일을 신산님이 검토·승인할 것. 기존 참고 시안의 실제 브라우저 시각 품질은 검증하지 않았으며 기존 시안 자체의 승인이 선행조건은 아님.
- 판매자·관리자의 나머지 세부 화면·편집 항목과 인수테스트 전 실제 시안 검토. 기존 시안은 참고만 사용한다.
- 출고 후 취소·교환·환불의 사유별 배송비·반송비 처리 및 약관 검토. 출고 전 적법한 취소의 상품금액·실제 결제 배송비 전액 환불 기준과 구분한다.
- PG 계약·요금, Oracle 환경, 카카오·Apple·문자·메일·앱 빌드의 실제 연동 검증 범위는 신산님 지정대로 인수테스트 준비 시점에 결정.
