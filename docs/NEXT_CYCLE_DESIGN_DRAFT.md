# 어울몰 다음 개발 주기 설계 초안

> 상태: 검토용 초안. 현행 승인 설계서·작업계획서를 대체하지 않는다. 2026-10-09 `design_change.md`의 미진을 실제 구현·검증 대상으로 되돌리기 위해 작성했다. 정본 설계·계획과 로컬 Git은 재대조했으며 WSL·PR 세부 상태는 별도 확인이 필요하다.

## 1. 목표와 유지할 계약

- 어울몰 브랜드·Flat v2, 구매자/판매자/관리자 분리, 어울몰 자체 판매자와 농가 판매자의 동일한 판매자 취급을 유지한다.
- 판매자별 분리 주문과 통합 결제, 발생 시점별 정산 장부, 관리자 개별 정산 완료 기록, 자동 송금 제외를 유지한다.
- 공유 개발 DB에는 불변 정산 시험 거래 행을 남기지 않는다는 신산님 결정을 유지한다. 격리 DB 검증을 공유 DB 실거래 행 검증으로 표시하지 않는다.
- 외부 실제 발송·수신과 사용자 인수테스트는 현 개발 완료 범위 밖이며, 공급자 mock/계약 시험과 로컬·WSL 실제 DB/API/브라우저·Android 에뮬레이터 검증은 구분한다.

## 2. S6 정산 미진

### 2.1 사유 있는 장부 정정

승인된 정산 계약은 기존 장부 행 덮어쓰기를 금지하고 정정 사건을 남기도록 요구한다. 현재 구현에는 이를 관리자가 안전하게 생성·조회하는 공개 경로와 시험이 확인되지 않았다. 후속 설계에서는 원장 사건 링크, 정정 사유·담당자·발생 시각, 원화 정수 금액 부호, 중복 요청 방지, 권한·감사 이력, 이미 완료된 기간 이후 정정 귀속을 함께 정의해야 한다. 정정은 원장을 수정하지 않고 새 발생 사건으로 기록하며, 과거 완료 스냅샷을 소급 변경하지 않는 방향을 **제안**한다. API·DB 계약 확정 전에는 구현하지 않는다.

2026-10-09 코드 대조에서 확인한 구체적 제약: `0020_s6_settlement.sql`은 `correction` 종류를 허용하지만 `amount_won > 0`만 허용하고 원사건을 가리키는 전용 외래키가 없다. `summary.ts`는 종류별 양의 금액만 합산하므로 정정이 원사건을 증가시키는지 감소시키는지 구분하지 못한다. `controller.ts`의 관리자 쓰기 경로는 완료·수수료뿐이다. 따라서 기존 칼럼에 임의의 `correction` 행을 넣는 것만으로 사유 있는 정정 계약을 만족하지 않는다. 후속 계약안은 **원사건 참조, 증가/감소 방향과 대상 항목, 원금액 초과 여부, 멱등 요청 ID, 관리자 권한·감사, 과거 완료기간과 신규 발생일의 관계**를 확정해야 한다. 모든 항목은 제안이며 기존 승인 범위에 포함된 것으로 취급하지 않는다.

### 2.2 공유 DB 검증 경계

신산님은 정식 `shoppingmall` 공유 DB에 불변 QA 거래 행을 남기지 않기로 했다. 원 작업계획의 공유 DB 행 기반 E2E 완료조건과 충돌한다. 선택지는 (A) 기존 조건을 유지하고 해당 E2E를 미검증으로 남김, (B) WSL의 별도 일회성 PostgreSQL DB에서 같은 후보 SHA/API/브라우저 흐름을 검증하고 정식 DB에는 migration/health/read-only 계약만 검증하도록 계획을 변경함이다. 현재는 A 상태이며, B가 정식 gate를 대체하는 것으로 자동 승인하지 않는다. 다음 계획 문서에는 이 차이와 잔여 위험을 명시한다.

### 2.3 검토·병합

PR #15는 검토용·미병합이다. 독립 리뷰와 Critical/Important 해소, 최신 HEAD의 로컬/WSL 정확한 SHA 검증, PR 본문의 목적·영향·검증·미검증·복구, 병합 후 smoke가 필요하다. CI 성공만으로 이 gate를 대체하지 않는다.

## 3. S7 Android 앱

- S7.0: 어울몰 아이콘 검토용 시안 2개가 있다. 어느 것도 승인된 기준 자산이 아니다. 승인 전 앱 자산 적용과 릴리스 후보 빌드를 하지 않는다. 기준 확정 후 adaptive icon 전경·배경, 원본 권리, 48px 가독성, 마스크 안전 영역, 에뮬레이터 홈 표시를 검증한다.
- S7.1: 웹과 동일한 가격·재고·배송비·할인·주문 상태 계약으로 탐색·상세·장바구니·결제 mock·주문/배송 조회·문의·알림 설정을 구현한다. 세션 만료·오프라인·품절·결제 실패·푸시 거부의 대체 경로를 시험한다. 아이콘과 무관한 계약 시험은 선행 가능하지만 Android 빌드 gate는 S7.0 뒤에 둔다.
- S7.2: 카카오/PG/푸시는 교체 가능한 adapter와 mock 경계를 둔다. 실제 공급자 응답·실기기 수신은 U0/U3 승인 범위로 구분하고 Expo Go 결과를 native 검증으로 표시하지 않는다.

## 4. S8 전체 검증

S1~S7 후보가 갖춰지면 고객·판매자·관리자 연결 회귀, 권한·동시성·접근성, 세 viewport/키보드/인쇄, Android 에뮬레이터, 성능 계측을 실행한다. Critical/Important 미해결 0과 실행한 검사별 실제 증거를 요구한다. 이어 로컬 branch의 정확한 SHA를 WSL 정식 checkout에 반영하고 API/DB/웹 대조, 백업·rollback·임시 자원 정리를 기록한다. 공유 DB 정산 거래 행 미검증은 명시적으로 남기며, 합의되지 않은 대체 검증으로 PASS 처리하지 않는다.
