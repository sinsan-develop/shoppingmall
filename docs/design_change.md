## Task 4 — 공유 WSL 30분 부하 실행 창

- 판정: 현재 공유 WSL 자원에서 100 동시 사용자·30분 부하는 실행하지 않는다. 읽기 시점 2 vCPU의 load average 4.95/7.06/6.41, swap 사용 5.0/8.0 GiB이고 다른 서비스 컨테이너가 다수 실행 중이다. `k6` 실행 파일과 SeaweedFS 4.47 이미지는 확인되지 않았다.
- 영향: 계획의 30분 p95·5xx·주문/재고/정산 정합성은 미검증. 기존 서비스의 성능 저하를 피하기 위해 보호 `shoppingmall` DB 및 공유 서비스에 부하를 걸지 않았다.
- 조치/재개 조건: 독립 로컬·격리 1사용자 smoke와 도구/자원 준비를 먼저 진행한다. 공유 시험 전 실제 한가한 시간대에 CPU·swap·디스크·서비스 영향을 재측정하고 정확한 대상 SHA·QA DB ID·자동 중단 임계치·복구 경계를 기록한 뒤 계획 A4의 환경별 실행 승인을 대조한다. 서버가 계속 바쁘면 별도 격리 환경 시험만 부분 증거로 유지한다.

## Task 1~3 — 버전 있는 이미지·PITR 결합 복원 계약

- 판정: 승인 설계에는 현재 개발용 비공개 이미지 격리 파일만 정의되어 있다. SeaweedFS/S3의 객체 소유·버전·삭제 표식 및 7일 PITR/일일 14개/RPO·RTO의 제품 계약은 없다. 작업계획 A1~A3도 설계 확정과 공유 환경별 적용 승인을 별도 경계로 적었고, 신산님은 이번 실행에서 설계서 수정을 금지했다.
- 영향: 실제 이미지 저장소의 동일 시점 결합 복원, 7일/14개 및 RPO·RTO 실측을 PASS로 판정할 수 없다. 현행 파일 격리·실패 반례와 일회성 PG의 독립 시험은 계속 가능하다.
- 조치/재개 조건: 기존 상품 이미지 격리 시험과 보호 자료 불변을 검증하고, 저장소/보관/복구 계약 및 정확한 환경 적용 대상을 다음 설계변경 주기에 확정한다. 이번 주기에는 보호 DB archive 설정, 영속 WAL 역할·Secret, 실제 상품 이미지 이관을 하지 않는다.

## Task 5 — 판매자 본인 조회·인증 비동기 접수·실제 수신

- 판정: `GET /auth/seller-applications`의 공개 응답·보관 계약과 인증 전달 전용 작업 큐 계약은 승인 설계에 없다(A6·A8). 현행 발송 코드는 개발용 mock 또는 disabled이며 루트 `.env`의 SMTP 설정만으로 실제 발송 어댑터·소유 확인·비용 승인이 성립하지 않는다(A7).
- 영향: 자기 신청 대기·반려 재방문의 새 API와 처리시간 차이 방어를 임의로 출시할 수 없고, 정식 관리자 링크의 실제 수신을 검증했다고 주장할 수 없다. 기존 가입/복구의 mock 권한·실패 닫힘 회귀 및 응답 시간 측정은 계속한다.
- 조치/재개 조건: 다음 설계변경 주기에 공개 필드·권한·보관, 비동기 접수/재시도/감사, 실제 발송 공급자·발신자·소유 확인·비용·Secret 사용 경계를 확정한다. 이번 주기에는 공유 관리자 행 생성이나 외부 발송을 하지 않는다.
