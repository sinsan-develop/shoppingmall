## G1 — 0024 추가에 따른 전체 회귀 시험의 고정 migration 개수

- 판정: 0024는 격리 DB에서 적용·정정 시험을 통과했으나, 로컬 전체 `pnpm test`의 `apps/api/test/migration-preview.test.mjs`가 migration 총수를 24로 고정해 25건을 거부했다. 제품 SQL 실행 오류가 아니라 기존 정적 보호 시험의 확장 필요 사항이다.
- 영향: 로컬 전체 회귀 605건 중 1건 실패(434 통과·170 조건부 건너뜀). 정확한 파일은 승인된 새 작업계획의 변경 목록에 없어 신산님 지시대로 임의 수정하지 않는다. CI·일반 PR 병합 조건도 현재 충족하지 못한다.
- 조치·재개 조건: 기존 0000~0023 해시 불변 검사를 유지하면서 신규 0024 추가를 허용하는 **이 시험 한 곳의 범위 추가 승인**을 요청했다. 답변 전에는 파일을 변경하지 않고 typecheck·lint·build·격리 검증 등 독립 작업을 진행한다.

## G2 — 실제 OS 인쇄 창·브라우저 200% 직접 실측 제어 제한

- 판정: 동일 SHA의 격리 API/Web와 실제 Chrome 화면에서 운영자 로그인, 5월 원사건 X 10,000원·고정 기간 이력 및 10월 정정 Y -2,000원 표시를 확인했다. 그러나 화면의 `조회 결과 인쇄 · PDF로 저장`을 누를 때 브라우저 입력 명령이 시간 초과됐고, OS 창 제어는 대상 브라우저 URL을 안전하게 판별할 수 없다는 보호 경계로 이번 턴 사용이 중단됐다. OS PDF 저장 파일 열람·실제 브라우저 200% 확대는 직접 증거가 없다.
- 영향: G3는 미검증이다. CDP 자동 PDF·viewport 시험이나 화면의 인쇄 버튼 노출만으로 PASS 처리하지 않는다. 이후 PR 일반 병합 조건에도 영향을 준다.
- 조치·재개 조건: 이미 얻은 화면·DB 근거를 `WORK_STATUS.md`에 분리 기록한다. 안전한 OS UI 제어가 가능해질 때 관리자·판매자 각각 PDF 저장 파일과 200% 확대를 실측한다. 그렇지 않으면 작업계획 C의 검증 기준 변경을 신산님께 별도로 요청하고 새 승인이 있기 전 G3 PASS/병합으로 처리하지 않는다. 다른 범위 내 검증과 임시자원 정리는 계속한다.
