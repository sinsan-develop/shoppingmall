## G2 — 공유 개발 DB 0023 적용

- 판정: 별도 적용 승인 확인 전. 격리 PostgreSQL 15에서 0023 적용·재실행·기존 완료 행 존재 시 전체 거부/rollback은 검증했다. 공유 `WSL-server/local-postgres/shoppingmall`에는 적용하지 않았다.
- 영향: 공유 DB의 C2 스키마·읽기 smoke와 지정 계획 Task 4 Step 5가 미검증이다. 격리 DB 합격을 공유 DB 합격으로 표시하지 않는다.
- 조치·재개 조건: 사용자에게 0023만의 별도 적용 승인을 요청한 상태다. 승인 시 적용 직전 DB 식별자·migration 이력·기존 완료 행·SQL 해시·백업/복구를 다시 확인하고, 계획대로 0023만 적용한다. 승인 없거나 상태가 다르면 공유 DB 쓰기 없이 이 항목을 유지한다. 가상 불변 정산 거래 행은 공유 DB에 만들지 않는다.

## G3 — OS 인쇄 창 PDF 저장·실제 200% 확대

- 판정: 두 동작 모두 미검증. 동일 제품 코드의 격리 실제 브라우저에서 관리자·판매자 조회, 1440/430px, Tab 포커스, CDP 생성 PDF와 금액은 확인했다. 그러나 OS 인쇄 창의 `PDF로 저장` 선택과 브라우저 실제 200% 확대를 직접 입증하지 못했다. 마지막 실측은 인쇄 버튼 뒤 브라우저 제어 시간 초과로 끝났고, 시험 자원은 정리했다.
- 영향: 지정 계획 Task 4 Step 6과 Task 5 병합 게이트에 필요한 직접 실측 증거가 없다. CDP PDF·좁은 viewport로 대체하지 않는다.
- 조치·재개 조건: 지원되는 실제 브라우저에서 사용자에게 보이는 인쇄 창 저장 결과와 200% 상태를 별도로 확인한다. 도구상 실측이 불가능하면 대체 증거와 미검증 범위를 제시해 신산님이 검증 기준을 직접 바꾸기 전까지 해당 게이트를 통과로 표시하지 않는다.
- 이번 재시도의 보안 경계: 별도 Chrome 시험 탭에서 로컬 파일 URL을 열려 했으나 브라우저 보안 정책이 해당 프로토콜을 차단했다. 차단된 주소를 다른 경로로 우회하지 않았으며 제품 실측 증거는 추가되지 않았다.

## G4 — 정정 사건의 발생 당시 분류 귀속 충돌

- 판정: 설계서 R09와 지정 계획 Task 3 Step 3은 정정 사건 자체의 발생 당시 판매자 분류를 요구한다. 판매자가 X에서 Y로 바뀐 뒤 Y 시점에 정정하면 Y 귀속이어야 한다. 현재 C1 `correction.ts`는 원사건의 X를 복사하고 0022 DB 트리거도 동일 분류를 강제한다. 해당 계약은 충족하지 못한다.
- 영향: X/Y 정정 집계와 독립 리뷰의 Important 0 조건을 충족하지 못해 Task 5 병합·병합 후 확인을 진행할 수 없다. 다른 X/Y 일반 사건·0건 완료 검증과 구분한다.
- 조치·재개 조건: 이번 계획은 C1/0022 재구현·수정 및 기존 migration 변경을 금지한다. 임의로 코드·DB를 확장하지 않는다. 별도 후속 계획에서 정정 기록 경로와 신규 migration의 정확한 SQL·영향·복구안을 정하고 승인받아, 기존 불변 사건을 재작성하지 않는 방식으로 X→Y 정정을 시험 우선 구현한다.
