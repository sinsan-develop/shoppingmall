## 2026-10-11 R16 검토에서 발견한 접수·재시도 경계

- 교차 작업 후속 판정: 옛 접수 완료 SQL 실패→새 접수 링크 전달→옛 접수 재시도에서 전달 5회/예상 4회를 격리 DB RED로 확인했다. 0027에 작업 ID 및 모의 전달 실패 표지를 추가한 뒤 정확 SHA 격리 DB 9/9·로컬 전체 0 fail로 GREEN을 확인했다. 같은 작업의 전달 성공 이력이 있으면 이후 토큰 폐기/소비와 무관하게 옛 작업을 재발급하지 않고, 모의 전달 자체가 실패한 작업만 재시도한다. 외부 전달의 원자적 exactly-once 보증이나 실제 수신은 이 증거에 포함되지 않는다.
- 적용 경계: 신규 0027은 격리 전용 DB에서만 적용했다. 고정 QA DB는 마지막 읽기 전용 확인 기준 migration 0026이고 보호 `shoppingmall`은 별도 승인 경계다. 0027 적용 전 해당 DB에서 R16 작업자를 실행하면 열 부재로 실패할 수 있으므로 서비스 구동·배포 합격으로 취급하지 않는다. 정확한 DB별 백업·SQL 해시·복원 근거를 갖춘 후 별도 승인과 후속 계획에서 적용해야 한다.

- 후속 미검증 경계: 기존 작업의 링크가 별도 새 접수의 토큰 발급으로 폐기된 뒤, 기존 작업의 지연 재시도가 새 링크를 다시 폐기할 가능성을 코드에서 발견했다. 한 작업의 완료 SQL 실패→새 작업 접수·전달→기존 작업 재시도 순서를 격리 DB에서 재현하기 전까지 교차 작업 재시도의 안전성을 `UNVERIFIED`로 둔다. 다음 실행에서 실패 시험 후 동일 R16 승인 범위 안의 보정을 검토하며, 실패를 기록 없이 PASS로 바꾸지 않는다.

- 후속 판정: 전달 뒤 완료 SQL 실패·리스 재획득의 중복 발급과, 이를 막는 시각 기준 보정이 별도 동시각 접수를 건너뛰는 결함은 격리 DB RED→GREEN으로 보정했다. 이미 QA DB에 적용된 0026은 원상 유지하고 추가 SQL을 새 0027로 분리했다. 0027 적용 후 격리 DB에서 인증 접수·복구·HTTP 8/8과 migration 역사 3/3을 확인했다. 공유 DB 적용이나 실제 수신을 뜻하지 않는다. 아래 최초 판정은 발견 당시 이력이다.
- 잔여 경계: 실행 API에 개발용 mock sink가 등록되지 않은 구성은 의도적으로 503 실패 폐쇄된다. 시험에서 주입한 sink의 결과를 일반 서버 수신함·실제 메일 성공으로 취급하지 않는다. 외부 발송은 계획 범위 밖이며, 실행 서버 mock 수신함 공개는 비밀 링크 노출 위험이 있어 후속 설계·승인 없이는 추가하지 않는다.

- 판정: 코드 검토에서 중요 결함 후보 두 건을 확인했다. 일반 API 시작 경로는 개발 mock sink를 등록하지 않으므로 가입·복구 접수가 503으로 거부된다. 이는 외부 발송 미구성 시 실패 폐쇄 의도와 일치하지만, 실행 중인 서비스의 R16 실제 접수 증거는 아니다. 작업자는 링크를 전달한 뒤 별도 SQL로 job을 완료 표시한다. 전달 직후 그 SQL이 실패하거나 프로세스가 종료되면 재시도에서 새 링크를 발급하며 앞선 링크를 폐기할 수 있다.
- 영향: 현재 격리 시험의 주입된 mock sink 성공과 HTTP 시험만으로 운영형 mock 접수나 발송 후 실패의 중복 안전성을 합격 처리할 수 없다. 링크가 이미 전달된 사용자에게 무효화가 발생할 수 있어 R16 재시도 조건은 `UNVERIFIED`다.
- 수행 조치: `delivery.ts`·`main.ts`·`intake-worker.ts`·`action-tokens.ts`와 관련 시험의 호출·트랜잭션 경계를 대조했다. 응답 전 분기 없음과 기존 실패 폐쇄 동작은 유지하고, 비밀값 저장이나 실제 외부 발송은 추가하지 않았다. 독립 가능한 Stage 4 가드와 Stage 5 로컬 회귀를 계속했다.
- 재개 조건: 동일 접수 job의 전달 성공 후 완료 SQL 실패·lease 재획득을 격리 DB에서 RED로 재현한다. 발급 토큰과 전달의 멱등성을 보존하는 승인 범위 내 보정이 가능하면 GREEN과 전체 회귀를 실행한다. 영속적 토큰 원문·새 공급자 계약 또는 새 migration이 필요하다면 현재 승인 범위를 임의 확대하지 않고 후속 설계·승인 경계로 남긴다. 실행 API mock 수신함 경로도 외부 발송·보안 경계를 늘리지 않는 방식이 확인될 때만 추가한다.
