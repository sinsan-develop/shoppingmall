# 초기 관리자 계정 준비·복구 절차

이 절차는 `WORK_PLAN_20260-10-10-1.md` Task 2의 구현 경계다. `admin`은 공개 로그인 ID가 아니라 서버가 부여하는 역할이다. 기존 관리자 계정이 있거나 활성화된 계정의 비밀번호 복구는 초기 등록을 다시 실행하지 않고 별도 복구 절차를 따른다.

## 실행 전 확인

1. 운영 담당자가 계정 소유자와 수신 이메일을 별도 채널에서 확인하고 그 사실을 기록한다. 이메일은 루트 `.env`의 `EMAIL_TO`를 기준으로 사용하며, CLI의 `INITIAL_ADMIN_EMAIL`을 별도로 지정했다면 두 값이 일치해야 한다. 값 자체를 티켓·채팅·로그·PR에 복사하지 않는다.
2. 공유 개발 DB의 지속 관리자 행 생성, 공급자 발송·Secret·비용은 각각 신산님의 별도 승인을 받은 뒤 진행한다. `0025` 적용 승인만으로 계정 행을 만들 수 없다.
3. 현재 CLI는 development+loopback+격리 QA DB의 비공개 IPC 모의 수신함만 허용한다. 실제 메일 공급자 어댑터가 승인·구현되기 전에는 공유 DB에서 실행할 수 없고, 링크를 stdout/HTTP 응답에 내보내는 우회도 허용하지 않는다.

## 격리 QA 절차

- 정확한 시험 DB 이름과 PostgreSQL system ID를 확인하고 `PGDATABASE`, `AUTH_ADMIN_TEST_DB_SYSTEM_ID`, 명시적 `DATABASE_URL`을 지정한다. `AUTH_DELIVERY_MODE=mock`, `APP_ENV=development`, `API_HOST=127.0.0.1`, `AUTH_LINK_ORIGIN`의 루프백 출처, `AUTH_AUDIT_HMAC_KEY`, `INITIAL_ADMIN_OPERATOR`를 시험 환경에만 둔다.
- 명시적 `--owner-confirmed` 인수와 QA harness의 비공개 IPC 수신함으로 CLI를 실행한다. 이 인수는 운영 담당자의 실제 소유 확인을 대체하지 않는다. 수신함은 raw 링크를 일반 로그로 출력하지 않는다.
- 발급 전에는 해당 이메일의 암호·확인 시각·세션이 없어야 한다. 30분·1회용 설정 링크를 소비한 뒤에만 비밀번호 해시와 이메일 확인 시각이 생성된다. 화면에서 새 비밀번호를 설정한 뒤 별도 로그인으로 관리자 역할을 확인한다.
- 같은 비활성 계정의 재발급은 소유자 재확인 뒤 이전 링크를 폐기한다. 활성 관리자나 다른 관리자 계정이 있다면 새 계정을 만들지 않는다.

## 실패·복구

- 발송 설정/수신 실패 시 링크는 폐기하고 활성 세션을 만들지 않는다. 비활성 계정은 별도 확인 뒤 같은 계정으로 재발급할 수 있다.
- 잘못된·만료된·이미 쓴 링크는 로그인이나 비밀번호 변경에 사용할 수 없다. 활성 관리자의 분실 비밀번호는 일반 비밀번호 재설정 절차를 사용한다.
- 배포 복귀 시 아직 유효한 초기 설정 링크를 폐기한다. 공유 DB `0025`는 자동 역마이그레이션하거나 전체 복원하지 않고 계정·세션·수단 영향과 백업을 대조해 별도 복구 승인을 받는다.

실제 공급자 수신과 정식 관리자 지속 행 생성은 현재 격리 QA 결과와 구분해 미검증으로 남긴다.
