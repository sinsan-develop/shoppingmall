# 어울몰 다음 개발 주기 작업계획 초안

> 상태: 검토용. 기존 `docs/WORK_PLAN.md`와 `docs/design/DESIGN.md`를 대체하거나 승인 경계를 면제하지 않는다. 입력은 2026-10-09 `design_change.md`와 정본 설계·계획의 최신 읽기 결과다. 로컬 Git은 재대조했고 WSL·PR 세부 상태는 별도 확인이 필요하다.

## 공통 진행 원칙

1. 이 주기의 미진을 실제 완료로 전환하되, 막힌 항목은 `design_change.md`에 대상·사유·증거·영향·실제 수행/미검증·재개 조건을 기록하고 독립 작업을 계속한다. 기록에 따른 진도 완료와 실제 PASS를 분리한다.
2. S6 PR #15와 현재 branch를 먼저 정리한다. 미병합 S6를 건너뛰어 S7 구현 branch를 새로 만들지 않는다. `main` 직접 개발·커밋 금지, 동일 기능 단일 writer, SSH 별칭 사용, GitHub 계정 기반 작업 금지.
3. 실제 DB/권한/공개 API·Secret·외부 비용·파괴적 조치는 기존 승인 범위와 별도 경계를 확인한다. 결정을 요구할 사안은 반복 질문으로 현 작업을 끊지 않고 `design_change.md`에 대안·권장안·재개 조건을 기록한다. 승인되지 않은 변경을 실행하지 않는다.
4. 실제 발송·실기기 공급자 결과·사용자 인수는 이번 개발 검증과 구분한다. 테스트 결과는 후보 SHA·환경·데이터 범위·실행 시각·정리 상태를 함께 기록한다.

## R0 — 실행 환경·정본·작업 상태 복구

- 입력: 현재 S6 worktree, `design_change.md`, `WORK_STATUS.md`, PR #15, PMO/프로젝트 지침.
- 수행: 로컬 실행기 복구 여부를 확인하고 최신 `WORK_PLAN`, `DESIGN`, `DEVELOPMENT_ENVIRONMENT`, 실제 branch/HEAD/dirty/untracked·remote PR head·WSL checkout/DB migration 상태를 읽기 전용으로 대조한다. 정본 설계·계획과 로컬 Git 대조는 재개됐으며 WSL·PR·DB 최신 상태는 별도로 검증한다. 문서 패치를 diff로 검토한 뒤 안전한 commit/push 경로를 판단한다.
- 완료 증거: 기준 commit, 각 문서 경로/버전, 수정 파일 목록, 미검증과 충돌, 임시 자원 잔류 여부가 `WORK_STATUS`에 기록됨. 실행기 장애가 지속되면 실제 검증 불가로 남기고 다음 독립 문서 작업만 진행한다.

## R1 — S6 정산 미진·PR gate

- R1.1 계약: 원장 정정의 원사건 링크·금액 부호·사유·권한·멱등성·발생일/완료기간 귀속을 설계하고 기존 승인 계약과 비교한다. 공개 API/DB 변경 전 별도 결정 경계를 기록한다.
- R1.2 RED: 결제·환불·수수료 중복, 완료된 기간 이후 정정/환불, 판매자 타인 조회·완료 거부, 전체/분류/개별 합계와 인쇄 차이, 기간 중복을 실패 시험으로 확인한다.
- R1.3 GREEN: 승인된 범위만 구현한다. 기존 장부/완료 행을 덮어쓰거나 삭제하지 않는다. 수수료 부담·자동 지급액·송금은 범위 밖이다.
- R1.4 검증: 로컬 test/typecheck/lint/build, 격리 실제 PostgreSQL, HTTP·관리자 브라우저·인쇄/PDF, WSL 정확한 SHA와 정식 DB migration/health를 분리 기록한다. 공유 DB 거래 행은 신산님 결정대로 남기지 않으며 행 E2E는 대체 gate가 승인되기 전 `미검증`이다.
- R1.5 독립 리뷰: Critical/Important 0과 보안/권한/데이터 보존, PR 설명·CI·rollback 증거를 확인한다. 필수 gate가 충족되지 않으면 PR #15를 병합하지 않고 미충족 조건을 기록한다. 병합되면 merged-main smoke 후 branch/worktree·임시 자원을 정리한다.
