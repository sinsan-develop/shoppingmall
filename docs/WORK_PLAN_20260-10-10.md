### 0024 SQL 계약 — 구현·승인 시 대조할 제안

`CREATE OR REPLACE FUNCTION validate_settlement_correction() RETURNS trigger`로 기존 트리거의 함수만 교체한다. 기존의 `original.kind <> 'correction'`, 동일 `seller_id`·`seller_name`, 유효한 원사건 링크 검사는 유지한다. **원사건과 새 사건의 `seller_category_id/name` 동일성 검사만 제거**하고, 아래 조건으로 바꾼다.

```sql
SELECT seller.category_id, category.name
  INTO current_category_id, current_category_name
  FROM sellers seller
  JOIN seller_categories category ON category.id = seller.category_id
 WHERE seller.id = NEW.seller_id
 FOR SHARE OF seller, category;
IF NOT FOUND
   OR current_category_id IS DISTINCT FROM NEW.seller_category_id
   OR current_category_name IS DISTINCT FROM NEW.seller_category_name THEN
  RAISE EXCEPTION 'Settlement correction seller category mismatch'
    USING ERRCODE = '23514';
END IF;
```

기존 `settlement_events_correction_original_valid` 트리거·불변 트리거·원사건 행은 재생성하거나 갱신하지 않는다. `recordCorrection`도 원사건 잠금 뒤 같은 트랜잭션에서 현재 판매자/분류 행을 `FOR SHARE`로 읽고 INSERT의 분류 값에 사용한다. 분류 변경과 경합하면 일관된 한 분류로 직렬화하거나 전체 요청을 롤백한다. 이 SQL은 **계획 계약 초안**이며 실제 적용 전 전체 함수 SQL·lock 순서·해시·DB 상태를 리뷰한다.
