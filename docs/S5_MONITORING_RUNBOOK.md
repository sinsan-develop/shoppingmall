# 관리자 관제 운영 Runbook (S5.4)

## 적용 범위와 숫자

- 대상 화면: `/account/admin/monitoring`, 관리자 세션만 조회할 수 있다. 응답은 `private, no-store`이며 운영자가 조회/새로고침할 때 갱신한다. 자동 경보·자동 복구·실시간 SLA는 없다.
- 주문 건수: 선택한 한국 날짜에 생성된 통합 주문 수. 주문 상태 필터를 적용한다. 상품매출: 선택한 한국 날짜에 결제 완료된 발송 주문의 상품 실결제액 합계로 배송비·배송비 지원은 제외하고 이후 환불액은 차감하지 않는다. 이는 농가 지급액/정산액이 아니다.
- 재고: 조회 시점의 공개 옵션과 판매 가능 0개 옵션 수. 클레임: 기간 내 접수 건수이며 클레임 상태 필터를 적용한다. 승인 대기·재고 이상·미처리 문의와 진행 중 클레임 목록은 현재 상태를 보여주므로 날짜 필터와 무관하다. 진행 중 클레임 목록에는 선택한 클레임 상태도 적용된다. 실패 결제는 시도일, 미출고는 결제일 기준이다.
- `전체 판매자`는 농가별 수치를 섞어 하나의 판매자로 취급하지 않는다. 판매자 필터의 주문·상품매출·실패 결제는 원판매자 상품 라인, 미출고는 출고 담당 판매자, 재고·문의·클레임은 소유 판매자 기준이다. 통합 주문은 두 판매자가 섞여도 전체 건수에서 한 번만 센다. 실패 결제의 `통합 결제 요청액`은 선택 판매자의 몫이 아니라 해당 통합 주문 전체의 결제 시도 금액이다.
- 각 예외 목록은 최신 50건만 표시하며 요약 수치는 전체 대상의 합계다. 목록 건수와 요약이 다르면 제한 때문인지 먼저 확인한다.

## 확인·조치 순서

1. 관리자 계정으로 로그인하고 기간·판매자·상태를 선택해 조회한다. 화면 상단 조회 시점과 숫자 기준을 먼저 확인한다.
2. 승인 대기는 `상품 요청 검토` 또는 `배송 정책 관리`의 해당 요청으로 이동한다. 상품/재고/판매중지/배송 요청 ID를 대조하고 기존 승인·반려 절차를 사용한다.
3. 미출고·지연은 해당 발송 주문 상세로 이동한다. 결제 시각·담당 판매자·출고 예정일·상태 이력을 확인하고 판매자에게 연락한 뒤 기존 출고 정정 절차를 사용한다. 관제 화면은 출고 상태를 직접 바꾸지 않는다.
4. 재고 이상은 공개 상품 상세에서 옵션 재고를 확인한다. 실제 보유수량과 다르면 판매자 확인·재고 요청/승인 절차를 거친다. 재고 0개를 승인 대기 동안 구매 가능하게 변경하지 않는다.
5. 미처리 문의는 `OPEN`(판매자 답변 대기) 또는 `ANSWERED`(운영자 공개 검토 대기)다. 문의 상세와 답변 이력을 확인한 뒤 기존 공개 절차를 사용한다. 클레임은 요청/답변/심사/환불 상태와 근거를 상세에서 확인하고 기존 승인된 심사·모의 환불 절차를 사용한다.
6. 실패 결제는 관제 항목의 결제 시도 ID·통합 주문 ID·통합 결제 요청액·시각·현재 주문 상태를 기록해 서버의 해당 결제 사건/시도 로그와 대조한다. 이후 재결제로 주문이 `PAID`가 되어도 과거 실패 시도는 이력으로 남으며, 화면의 `결제완료(이전 실패 이력)`은 현재 미결제가 아님을 뜻한다. 현재 별도 결제 시도 관리 화면과 수동 재처리 기능은 없다. 임의로 결제 상태·DB를 수정하거나 고객에게 재결제를 지시하지 않는다. 로그 원인 확인 후 정해진 결제 처리/고객 안내 절차로 넘긴다.
7. 조치 후 `새로고침`한다. 승인·공개·출고·결제 상태가 달라졌는지, 예외가 여전히 남는지 확인한다. 다른 기간/판매자 필터 또는 최대 50건 목록 때문에 사라진 것처럼 보일 수 있으므로 원자료 상태와 함께 대조한다.

## 장애와 복구

- API `401/403`은 계정 역할·세션을 확인한다. `400`은 날짜/UUID/상태 입력을 확인한다. `5xx`나 화면의 조회 실패는 해당 시각의 API 로그와 DB 연결 상태를 확인하되 임의 재시작·스키마 변경은 하지 않는다.
- 숫자 불일치가 의심되면 화면의 기간·판매자·상태·조회 시각, 대표 통합 주문/발송 주문/결제 시도/클레임 ID를 기록한다. 원자료를 읽기 전용으로 대조하고 금액의 배송비 제외, KST 경계, 전체 주문 중복 제거를 확인한다.
- 장애 복구·롤백은 프로젝트의 검증된 `main`/checkpoint 및 배포 Runbook을 따른다. 관리자 화면은 읽기 전용이며 롤백을 이유로 거래·고객정보·지속 데이터를 삭제하지 않는다. 운영 서버 전환과 실제 결제/발송은 별도 승인 대상이다.
