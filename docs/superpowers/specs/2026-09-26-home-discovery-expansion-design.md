# 어울몰 메인 화면 탐색 구조·확장 설계 초안

- 상태: 신산님 서면 검토 대기 (2026-09-26). 신산님은 네이버 쇼핑을 **장기 참조**로 지정하고 검색·메뉴·이벤트·상품 카테고리·개인별 추천 화면 예시를 제시한 뒤, 메인 화면을 이 구조로 하자고 결정했다. 본 문서는 어울몰의 구조 제안이며 기존 홈 시안의 교체나 모든 후속 기능의 즉시 구현 승인으로 해석하지 않는다.
- 정본: [PRD](../../PRD.md), [제품 설계](../../design/DESIGN.md), [기술 방향](../../TECH_STACK_PROPOSAL.md), [분류·등록 시안 설계](2026-09-26-category-registration-and-settlement-prototype-design.md), [현 작업 상태](../../../WORK_STATUS.md).

## 1. 의도와 채택 방향

고객이 상품을 **검색하거나, 메뉴·기획전·카테고리·추천 목록을 통해 발견**하고 상품 상세로 갈 수 있는 어울몰 홈을 만든다. 네이버의 정보 탐색 방식은 참고하되 로고·문구·이미지·서비스명·정렬 알고리즘을 복제하지 않는다. 제품명 어울몰, 황금·크림·먹빛 색과 기존 폰트 크기 기준, 전국 산지 상품 허용, 단일 브랜드몰의 통합 결제와 판매자 승인 체계는 유지한다.

비교한 방향은 (A) 현재 홈에 검색 아이콘과 고정 배너만 추가, (B) 아래 다섯 탐색 영역을 독립된 구성으로 설계하고 실제 기능은 단계적으로 개방, (C) 검색 광고·AI 개인화·라이브·외부 입점까지 한꺼번에 구축이다. **B를 권장**한다. A는 신산님이 제시한 홈 구조를 충분히 담지 못하고, C는 기존 승인 MVP·운영 능력·개인정보/비용 경계를 넘는다. 이 결정은 판매자 자율 입점이나 오픈마켓 전환을 뜻하지 않는다.

## 2. 위에서 아래로 보는 메인 화면

| 순서 | 영역 | 첫 출시에서 보여 줄 모습 | 나중에 확장할 자리 |
|---|---|---|---|
| 1 | 어울몰 로고·큰 검색창·계정/장바구니 | 상품명 입력 후 결과 목록으로 이동. 검색 대상은 기존 상품명·산지·판매자명과 승인된 공개 상품. 모바일에서도 입력 가능 | 검색어 제안, 최근 검색, 인기 검색, 오타·동의어, 결과 내 세부 필터. 개인 검색 기록은 동의·보관 기준 결정 후 |
| 2 | 상단 가로 메뉴 | 홈, 상품 분류, 기획전 등 **어울몰 자체 메뉴**. 화면 폭이 좁으면 메뉴 접근 경로 유지 | 관리자 표시/숨김·순서·기간 설정. 메뉴 대상은 승인된 내부 페이지로 제한; 새 서비스는 실제 기능을 갖춘 뒤 공개 |
| 3 | 이벤트·기획전 카드 | 제철 상품·선물 등 여러 카드의 제목, 이미지, 안내, 상품 모음 링크. 카드가 없으면 영역 숨김 | 기간 예약, 노출 순서, 판매자 제안→관리자 승인, 클릭 지표. 쿠폰·실할인은 기존 금액 정책과 별도 연결하고 배너만으로 할인 적용하지 않음 |
| 4 | 상품 카테고리 바로가기 | **대분류 아이콘** 선택 → 해당 소분류와 공개 상품 목록. `대분류 → 소분류 → 상품`을 유지 | 추가 카테고리의 가로 탐색. 특가·배송·라이브 등은 상품 분류가 아닌 별도 전시/서비스 바로가기로 관리 |
| 5 | 추천 상품 목록 | 관리자가 고른 제철·인기 상품 등 **모든 방문자에게 같은 편집 목록**. 상품명·이미지·가격·산지·배송 핵심 정보와 상세 링크 | 로그인 고객의 적법한 이용 데이터와 동의/설정에 따른 개인화. 개인화 결과가 없거나 실패하면 공통 편집 목록으로 복귀. 광고를 도입하면 추천과 명확히 구분해 표시 |

이 순서는 신산님이 순서대로 제시한 예시를 어울몰 홈 구조로 해석한 것이다. 상세 화면의 실제 여백·카드 수·모바일 전환은 클릭형 시안으로 검토하되, 네이버 화면의 픽셀 배치나 브랜드 자산은 복사하지 않는다. 상품 카드의 재고 0개/품절 차단, 가격·할인·배송비 표시와 결제 전 재검증은 기존 계약을 그대로 따른다.

## 3. 관리·데이터 경계

- **상품 분류와 전시 영역을 분리:** 상품은 관리자 정의 소분류에 속한다. 메뉴·기획전·추천은 그 상품을 가리키는 별도 전시 구성이다. 상품을 여러 홈 영역에 보여도 주문/재고의 원상품 식별자는 하나다.
- **공개 범위:** 승인 대기 상품, 판매 중지, 품절 상품의 노출/구매 가능 상태는 기존 승인·즉시 차단 규칙을 따른다. 판매자가 자기 상품이나 행사 전시를 제안해도 고객 화면 공개는 관리자 승인 후다. 어울몰 판매자도 같은 절차다.
- **관리자 편집:** 초기 시안에는 가상 홈 설정으로 노출 순서·링크를 보여 줄 수 있지만, 실제 저장 화면·권한·이력은 후속 상세 설계/DB 승인 대상이다. 메뉴의 관리자 직접 편집 범위와 이벤트의 할인 포함 여부는 신산님 답변 전 확정하지 않는다.
- **검색:** 검색 결과는 상품 공개 상태와 카테고리·판매자 범위를 일관되게 사용한다. 초기 기술은 승인된 PostgreSQL 검색 방향을 유지하며, 규모와 한국어 검색 품질의 실제 증거가 생기면 전문 엔진을 비교한다.
- **추천:** 초기 편집 목록은 개인화라고 표시하지 않는다. PRD의 AI 개인화는 Phase 2다. 행동 데이터 수집, 동의, 삭제/보관, 광고 구분, 추천 품질은 후속 설계와 승인 경계로 둔다.

## 4. 화면 상태와 수용 기준

- 검색어가 비었거나 결과가 없을 때 안내를 제공하고, 결과가 0개인 소분류는 다른 상품을 임의로 끼워 넣지 않는다. 이벤트 카드의 연결 상품/페이지가 비공개·삭제·기간 종료면 공개 카드에 남기지 않는다.
- 홈에 추천 상품이 없거나 추천 계산이 실패하면 공통 편집 목록 또는 명확한 빈 상태를 보인다. 실패가 검색·장바구니·결제까지 전파되지 않도록 한다.
- 키보드로 검색·메뉴·이벤트·카테고리·상품 카드에 접근할 수 있고 모바일 폭에서도 탐색 순서가 유지돼야 한다. 실제 브라우저에서 1920×1080, 1440×900, 430×844와 200% 확대를 확인한 경우에만 검증 완료로 적는다.
- 초기 클릭형 시안은 가상 자료이며 로그인 개인화, 관리자 저장, 실시간 검색, 할인 적용, 광고 집행·측정, 외부 판매자 입점이 구현됐다고 표시하지 않는다.

## 5. 기존 시안·향후 작업과의 관계

승인된 [정적 홈 v1](../../design/assets/home-v1.html)과 현재 [고객 클릭형 시안](../../design/prototypes/customer.html)은 보존한다. 이 문서는 **다음 홈 개편의 서면 설계**일 뿐 두 화면을 수정하지 않았다. 서면 승인 뒤 별도 구현 계획에서 홈 시안 수정 범위와 검증·rollback을 정한다. 미결정 사항은 관리자 메뉴 편집 권한/방식, 기획전 할인·쿠폰 연계, 실제 개인화 데이터 정책, 후속 입점 모델이다. 기존 PRD·DESIGN·WORK_PLAN의 승인 상태는 이 초안만으로 바뀌지 않는다.

## 6. `D:\Project\shoppingmall` 참고 화면의 재활용 범위

신산님이 다시 지정한 기존 폴더의 `index.html`, `seller.html`, `operator.html`, `app.js`, `styles.css`를 **읽기 전용**으로 대조했다. 기존 폴더는 변경·미추적 파일이 있는 별도 참고 저장소이므로 현재 코드 정본으로 복사·병합하지 않는다. 상세 충돌 사항은 [기존 자료 반영 검토](../../design/REFERENCE_REVIEW.md)를 따른다.

| 기존 화면에서 가져올 흐름 | 어울몰 현행 개념에 맞춘 반영 |
|---|---|
| 구매자 검색창·프로모션 카드·쇼핑 바로가기·카테고리 탭·상품 그리드 | 이 문서의 홈 영역과 분리된 `상품 카테고리`/`쇼핑 바로가기`에 반영. 상품 상세의 이미지·옵션·안내 탭, 장바구니 수량·제거, 주문 내역과 문의/리뷰는 기존 PRD의 고객 여정으로 유지 |
| 판매자 상품 등록·이미지 URL/상세 이미지 구분·미리보기, 재고, 주문 검색·상태 필터, Q&A·클레임·정산 메뉴 | 역할별 업무 정보구조의 참고. 실제 제품은 파일 URL 입력이 아닌 승인된 업로드 경계, 관리자 정의 소분류 선택, 자기 판매자 범위, 공개 변경의 관리자 승인을 적용. 판매자는 환불 최종 처리·정산 완료를 하지 않음 |
| 운영자 대시보드·고객/재고/배송/클레임/정산·프로모션·배너 관리 | 전체 예외 조회와 운영 화면 구성 참고. 배너/쿠폰은 서로 다른 규칙과 승인을 갖고, 정산은 판매자 분류/판매자별 발생 항목·기간 완료 기준을 따름. 운영 지표와 알람 수치는 별도 실측/승인 필요 |

가져오지 않을 것은 N+ 형태의 표식·네이버 유사 서비스명, A/B/C 테마 전환, 디지털/패션 샘플 상품, `localStorage`를 실제 거래 정본으로 사용하는 방식, 고정 PIN `0000`, 3.5% 자동 정산 예정액, 판매자 직접 환불, 기존 `/buyer`·`/seller`·`/operator` URL·9088 포트의 자동 채택이다. 기존 폴더의 시각·업무 아이디어를 최대한 활용하되 **현재 승인된 어울몰 브랜드·농산물/전국 산지·발송 주문 분리·통합 결제·관리자 권한**을 덮어쓰지 않는다.
