# 어울몰 역할별 독립 클릭형 시안 설계

- 상태: 신산님 승인(2026-09-26). 구현 계획은 별도 검토 대상
- 기준: [승인된 PRD](../../PRD.md), [제품 설계](../../design/DESIGN.md), [정적 시안 안내](../../design/assets/README.md)
- 결정: 신산님은 고객·판매자·관리자 **역할별 독립 클릭 시안**을 선택했다. 정적 화면 4개는 승인된 시각 기준으로 보존한다.

## 1. 목적과 성공 기준

비개발자인 신산님이 실제 계정·결제·서버 없이도 주요 구매와 운영 절차의 화면 순서, 안내 문구, 권한 경계, 예외 표시를 눌러 검토할 수 있게 한다. 클릭형 시안 승인은 UI 흐름 승인이지 상품 금액·법률 정책·기술 연동 또는 제품 기능의 검증을 뜻하지 않는다.

성공 기준은 고객이 분할 주문과 통합 결제 안내를 따라가고, 판매자가 자기 담당 업무의 즉시 반영과 승인 대기를 구별하고, 관리자가 승인·환불·농가별 정산 완료의 책임을 구별할 수 있는 것이다. 모든 화면은 현재 승인된 어울몰의 황금·크림 시각 디자인과 참조 저장소의 글자 크기 체계를 유지한다.

## 2. 선택한 구성과 대안

`docs/design/prototypes/`에 고객·판매자·관리자 시안을 각각 하나의 독립 HTML 진입점으로 둔다. 공통 시각 CSS와 필요한 최소 JavaScript를 공유하되, 각 시안의 가상 상태는 다른 시안에 전달하지 않는다. 새로고침하면 해당 시안의 초기 상태로 돌아간다. 판매자 시안의 요청과 관리자 시안의 승인 예시는 같은 업무 규칙을 설명하는 별개의 가상 사례이며 실제로 서로 동기화되지 않는다고 표시한다.

역할 간 상태를 공유하는 통합 데모는 승인 전후 고객 공개의 연속 변화를 보이기 쉽지만, 신산님이 선택한 독립 구성과 다르므로 채택하지 않는다. 화면마다 여러 HTML 파일로 나누는 방식은 이동 경로가 늘어나므로, 각 역할의 한 진입점 안에서 단계/탭을 전환한다. 기존 정적 HTML 4개는 클릭 기능 개발 대상으로 수정·대체하지 않는다. 승인 전이라는 오래된 상태 문구만 실제 승인 상태에 맞게 정정한다.

## 3. 역할별 시나리오

### 고객 시안

1. 홈/상품 카드에서 상품 정보와 산지·발송 주체를 확인한다. 초기 대표 품목 5종은 가상 자료다.
2. 가상 장바구니에서 농가 A 고추 52,000원, 농가 B 양파 30,000원, 어울몰 발송 마늘 18,000원을 예시로 선택한다. 재고 0개인 예시 옵션은 담기와 결제 진행을 차단한다.
3. 결제 확인에서 세 발송 주문을 따로 보여 주되 한 번의 결제 합계 101,000원을 보여 준다. 농가 A는 할인 전 52,000원으로 무료배송, 나머지 두 주문은 배송비 3,000원씩이며 예시 할인은 5,000원이다. 총액은 100,000−5,000+6,000원이다.
4. 모의 결제 성공/실패를 선택해 완료 또는 실패 안내를 확인한다. 실제 결제창·PG 호출·주문 생성은 없다.
5. 완료 예시에서는 각 발송 주문의 배송·취소 상태를 별도로 보여 준다. 출고 전 발송 주문 전체 취소 예시는 그 주문의 실제 결제 상품금액과 배송비를 환불하고 다른 주문을 유지한다고 안내한다. 출고 후 환불의 배송비·반송비는 미확정이라고 표시하고 액수를 확정하지 않는다.

### 판매자 시안

1. 농가 A 담당 상품·주문만 보이는 예시로 시작한다. 농가와 어울몰 판매자는 동일 절차를 사용하며, 다른 판매자 범위는 보이지 않는다.
2. 무료배송 기준 50,000→60,000원 변경을 요청하면 `승인 대기`로 표시하고, 고객 공개 기준 50,000원은 유지한다. 재고 증가·품절 해제도 승인 대기 상태로 구분한다.
3. 재고를 0개로 표시하면 구매 차단 상태를 즉시 보여 준다. 출고 처리·운송장 입력은 승인 대기 없이 즉시 표시되는 별도의 예시로 제시한다.
4. 판매자 화면에는 고객 환불 최종 결정과 농가 정산 완료 버튼을 두지 않는다.

### 관리자 시안

1. 가상 판매자 요청을 열어 기존값·제안값·요청 역할/시각을 비교하고 승인 또는 반려한다. 이 시안 내부의 승인 결과만 변경하며 고객·판매자 시안에는 전달하지 않는다.
2. 출고 전 적법한 발송 주문 전체 취소 예시에서 실제 결제 상품금액과 해당 배송비 환불을 구분해 보여 준다. 출고 후 클레임은 사유/증빙 확인 단계까지만 시연하고, 법률·약관 미확정의 배송비·반송비 결론을 자동 제시하지 않는다.
3. 농가별 매출·수수료·배송비·할인·환불 발생 내역을 날짜·근거 주문과 함께 보여 준다. 관리자가 시작일·종료일을 선택하면 항목별 기간 합계를 표시하고 농가별로만 완료 여부를 바꿀 수 있다. 같은 농가의 이미 완료된 기간과 겹치는 재완료는 막는다.
4. 5월 1일 판매·5월 20일 정산 완료·7월 1일 환불 예시에서는 환불을 7월 1일 발생으로 표시하고 5월 원주문/상품을 근거로 연결한다. 최종 지급액 자동 결정·실제 송금은 시연하지 않는다.

## 4. 화면·상태와 데이터 경계

- 각 진입점에는 현재 역할·가상 시안 표시, 단계 이동, 처음부터 다시 보기, 완료/실패/승인 대기/품절/권한 없음 등 해당 시나리오에 필요한 상태 안내를 둔다.
- 시안의 버튼은 실제로 이동하거나 상태를 바꾸는 것과, 개발 범위 설명용 비활성 항목을 시각·문구로 구분한다. 중요한 조작 결과는 색뿐 아니라 텍스트로 알린다.
- 시험 이름·주소·주문번호·운송장은 명백한 가상값만 사용한다. 브라우저 저장소, 서버, DB, 외부 API, 실제 결제·송금·발송·알림·로그인 연결은 사용하지 않는다.
- 가격·수수료·정산 항목은 가상 사례이며 부담 주체와 최종 농가 지급액을 계산하지 않는다. 할인 배분이나 환불 예시는 승인된 PRD 원칙을 벗어나지 않는다.
- 실제 고객·판매자·관리자 권한 검사는 제품 구현에서만 가능하다. 이 시안의 역할 분리는 설명용이며 보안 검증으로 간주하지 않는다.

## 5. 검증과 인계

- 고객·판매자·관리자 각각의 시작→핵심 조작→결과→초기화 경로, 가상 결제 합계, 재고 차단, 승인 전 기준 유지, 농가별 독립 완료와 과거 판매/후속 환불 연결을 정적·자동 검사한다.
- 키보드 조작, focus, 상태 안내, 1920×1080·1440×900·430×844 및 200% 확대를 실제 브라우저에서 확인해야 한다. 파일 URL 보안 정책 등으로 검증하지 못하면 미검증으로 기록하며 우회 성공으로 표시하지 않는다.
- 시안 검토 뒤 신산님이 승인/수정을 결정한다. 이 문서 및 시안의 승인은 `docs/WORK_PLAN.md`의 제품 구현 착수 게이트, DB·인증·외부 계약·Oracle 배포 승인, 실제 사용자 인수테스트를 대신하지 않는다.
