# 인증 링크 SMTP 전달 설계

- 작성일: 2026-10-13
- 단계: 로컬·WSL-server 기능 구현(1단계)의 후속 설계. 이 문서만으로 제품 코드 변경·외부 발송·운영 배포를 승인하지 않는다.
- 기준: `docs/design/DESIGN.md` R13·R14·R16, `docs/WORK_PLAN_20260-10-11.md` Stage 3, `docs/design_change.md`의 R16 외부 전달 미구현 기록. 기존 두 정본 문서는 수정하지 않는다.

## 목표와 현재 경계

신산님이 가입과 비밀번호 복구를 사용자 화면에서 실제로 사용할 수 있도록, 이미 구현된 동일 응답의 비동기 접수·영속 작업자 뒤에 실제 SMTP 전달을 연결한다. 기존 `disabled`와 개발 루프백 `mock`은 유지한다. 현재 일반 실행은 전달 수단이 없어 503으로 실패 폐쇄되며, 격리 시험의 모의 수신은 실제 메일 수신 증거가 아니다. 초기 관리자 계정 생성·소유 확인, 문자, 외부 PG, Oracle 이전과 공개 배포는 이 설계의 대상이 아니다.

## 선택한 방식

기존 `auth_intake_jobs` 접수와 `processAuthIntakeOnce` 작업자를 유지하고, `delivery.ts`에 `smtp` 전달 모드를 추가한다. 공개 요청 중 SMTP를 호출하지 않는다. 다른 방식인 요청 중 즉시 발송은 응답 시간·계정 존재 추측·네트워크 실패가 공개 요청에 직접 영향을 주므로 채택하지 않는다. 별도 메시지 서비스나 새 큐 도입은 현재 기능에 필요하지 않아 하지 않는다.

## 동작 계약

1. 가입·복구 화면은 기존 공개 API를 그대로 사용한다. 형식·남용 제한을 통과한 요청은 계정 존재 여부를 공개 응답 전에 판단하지 않고 동일한 `{status:'accepted'}`를 반환한다. 설정이 불완전하거나 전달 모드가 `disabled`면 기존처럼 실패 폐쇄한다.
2. 작업자는 접수 후 기존 자격·역할·발급 제한을 확인한다. 적격한 경우에만 기존 만료·1회용 수단을 발급하고 SMTP로 링크를 보낸다. 미등록 복구와 중복 가입은 링크 없이 안전하게 종료한다. 공개 가입으로 관리자 역할이나 세션을 만들지 않는다.
3. `smtp`는 서버 측 전용 설정으로만 활성화한다. 시작 전 메일 서버·보안 연결·발신자·인증정보 존재와 `AUTH_LINK_ORIGIN`을 검증한다. 링크 출처는 승인된 HTTPS origin으로 제한하며 사용자명·비밀번호·검색식·임의 호스트가 섞인 URL은 거부한다. 개발 루프백 mock의 제약은 완화하지 않는다. 실제 설정값과 수신 주소는 문서·Git·일반 로그에 남기지 않는다.
4. SMTP 오류는 공개 응답이나 계정 존재를 드러내지 않는다. 작업자는 기존 시도 횟수·리스·만료 경계에 따라 재시도하고 최종 실패는 비밀 없는 코드로 기록한다. 재시도·경합에서 다른 접수 작업의 새 링크를 폐기하거나 동일 작업의 링크를 무제한 재발급하지 않는다. SMTP 수락과 실제 수신은 구분해 보고한다.
5. 원문 링크·토큰·SMTP 비밀번호는 작업 큐, 감사 DB, 예외 메시지, 일반 로그에 저장하지 않는다. 메일 제목·본문에는 목적과 일회용 링크만 넣고 비밀번호·관리자 역할 정보를 싣지 않는다. 메일은 요청에서 정규화된 대상 주소에만 보내며 임의 수신자 재지정 기능을 추가하지 않는다.

## 구현 경계와 검증

- 수정 대상은 기존 인증 전달·접수 작업자·시작 설정과 그 직접 시험, 필요할 때 가입·복구 화면의 오류 표시로 제한한다. 기존 인증 DB 계약과 0026·0027 SQL을 이 기능 때문에 변경하지 않는다.
- 먼저 격리 mock SMTP 서버에서 가입·복구 정상 흐름, 미등록/중복 계정의 무발송, SMTP 거부·시간초과·재시도·만료, 공개 응답 동일성, 링크·비밀 비노출을 확인한다. 기존 루프백 mock·disabled와 로그인/권한 핵심 회귀를 확인한다. 시험 기준을 낮추거나 조건부 skip을 실제 전달 성공으로 기록하지 않는다.
- WSL 정식 QA DB의 0026·0027은 각각 별도 승인된 적용·복원 확인이 끝나야 정식 작업자 검증에 쓴다. 보호 `shoppingmall` DB에 시험 거래를 만들지 않는다. 실제 외부 메일 시험은 노출된 옛 비밀번호의 교체 확인, 신산님의 정확한 수신 계정·발송 범위 승인, 링크가 열리는 HTTPS 주소와 환경 준비 후에만 한다. 그전에는 `구현했지만 실제 수신 미확인`으로 분류한다.
- 여러 브라우저·기기, 전체 회귀, 부하·복구 및 Oracle 검증은 2단계에서 위험에 맞게 수행한다. 외부 공개·운영 투입은 별도 결정이다.

## 중단·복구 기준

설정 검증 실패 시 SMTP 작업자를 시작하지 않고 실패 폐쇄한다. 발송 실패는 이미 접수된 작업의 상태·재시도 기록으로 추적하고, 비밀을 출력해 진단하지 않는다. 기존 `disabled` 모드로 되돌리는 것이 기능 차단형 복구이며, 이미 발송된 링크를 회수한 것으로 표시하지 않는다. 노출된 기존 메일 비밀번호는 교체 전 사용하지 않는다.
