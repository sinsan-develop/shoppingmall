> **For agentic workers:** REQUIRED SUB-SKILL: 구현 지시를 받은 뒤 `superpowers:subagent-driven-development` 또는 `superpowers:executing-plans`로 Task별 RED→GREEN→검증을 수행한다. `- [ ]`는 실제 증거가 있을 때만 표시한다.

**Goal:** 정식 초기 관리자 계정의 본인 비밀번호 설정과 로그인 화면의 가입·비밀번호 찾기를 역할·소유 확인·감사 이력에 맞게 제공한다.

**Architecture:** 기존 이메일 로그인·역할 grant·세션을 재사용하되, 공개 가입과 관리자 초기 설정을 분리한다. 서버가 해시로 보관하는 만료·1회용 수단을 검증한 뒤에만 계정 생성 또는 비밀번호 변경을 확정한다. 판매자 신청은 관리자 승인 전 역할을 주지 않는다. 발송은 개발용 격리 모의 어댑터와 출시용 공급자 경계를 분리한다.

**Tech Stack:** Node 24, NestJS 12/TypeScript, PostgreSQL 15/Drizzle, Next.js 16/React, Node 시험, Chromium 실제 화면.

**Spec:** `D:/Project/shoppingmall2/docs/design/DESIGN.md` R13·R14 및 2·4·5·6·7절, `D:/Project/shoppingmall2/docs/design_change.md`의 첫 두 후속 설계변경 요청. 아래 G1~G5는 과거 정산 작업의 상태 이력이며 이번 인증 기능의 재구현 근거가 아니다. 사용자 지정 파일명 `WORK_PLAN_20260-10-10-1.md`를 그대로 사용한다.

**보안 인터페이스 계약:** `issueActionToken(purpose, email, accountId, now)`는 원문을 호출 측 발송 어댑터에 한 번만 전달하고 DB에는 해시·만료·폐기 상태만 남긴다. `consumeActionToken(purpose, rawToken, now, transaction)`은 같은 트랜잭션에서 행을 잠그고 목적·만료·미사용을 검사해 한 번만 소비한다. 발송 어댑터는 `deliverAuthLink(purpose, email, url)`이며 정식 미설정은 명시 실패, 개발 mock은 격리 시험 harness로만 링크를 전달한다. 세션 폐기는 `auth_sessions.revoked_at`을 서버에서 갱신한다. 실제 함수 시그니처는 구현 전 이 계약과 기존 `AuthRepository` 구조에 맞춰 확정하고 공개 HTTP 의미를 바꾸지 않는다.

**환경·링크 계약:** `.env.example`에는 값이 아닌 `AUTH_DELIVERY_MODE`(`disabled` 기본, `mock`은 development+loopback, 실제 공급자 모드는 별도 승인), `AUTH_LINK_ORIGIN`(정식 HTTPS 허용 출처), `AUTH_AUDIT_HMAC_KEY`(운영 Secret)의 이름·역할만 적는다. 초기 관리자 식별자 `INITIAL_ADMIN_EMAIL`은 명시적 CLI 실행 환경에서만 읽는다. 브라우저 링크는 token을 URL **fragment**로 전달해 HTTP 요청·Referer에 포함하지 않고, 화면은 읽은 직후 주소창에서 제거한다. 토큰은 애플리케이션 로그·분석 도구에도 보내지 않는다. 비밀값·공급자 설정 부재 시 정식 환경에서 발급을 거부한다.

## 4. 판정·복구·인수 경계

- 항목별 판정은 **초기 관리자 설정, 구매자 가입, 판매자 신청/승인, 비밀번호 복구/세션 폐기, 격리 DB·브라우저, 공유 DB schema/읽기, 실제 발송, CI·PR, 병합 SHA**를 각각 PASS/FAIL/미검증으로 적는다. 개발용 mock 성공은 실제 메일·문자 수신 PASS가 아니다.
- 사용자 인수 절차에는 정식 관리자 소유 확인·첫 비밀번호 설정, 고객 가입, 판매자 승인, 재설정 후 모든 옛 세션 차단과 새 로그인, 잘못된 링크/권한 차단을 포함한다. 실제 채널·Oracle 환경이 준비되지 않은 단계의 결과를 운영 출시 승인으로 표시하지 않는다.
- 제품 코드 회귀는 원인과 마지막 검증 `main`을 대조해 별도 revert PR로 복귀한다. 이미 발급한 활성 일회용 수단은 배포 복귀 시 무효화한다. 공유 0025를 적용했다면 자동 역마이그레이션·전체 DB 복원을 하지 않고 계정·세션·신청 영향과 백업을 대조해 별도 복구 승인을 받는다.
- 정식 관리자 계정/전달 채널 미결정, 공유 DB 미승인 또는 공급자 계정 부족이 생겨도 승인 범위의 격리 구현·검증·문서화는 계속한다. 진도를 막는 사실은 `docs/design_change.md`에 판정·영향·조치·재개 조건을 기록하고, 해당 항목을 미검증으로 남긴다. 기록 자체가 시험 통과·출시 승인을 뜻하지 않는다.
