# 어울몰 제품 요구사항 문서(PRD)

- 문서 상태: MVP 범위·기술 계획 기준으로 신산님 승인(2026-09-26). 14절 미결정 사항과 법률·외부 계약은 승인 대상에서 제외
- 작성일: 2026-09-26
- 제품명: 어울몰
- 제품 유형: 계약 산지 농가 기반 농산물 직거래 커머스

## 1. 문서 목적

어울몰의 제품 목표, 고객 문제, MVP 범위, 운영 정책, 성공 지표를 정의한다. 본 문서는 개발 설계의 승인된 범위 기준이며, 법률·정산·배송 계약의 최종 정책을 대신하지 않는다.

## 2. 제품 개요

어울몰은 계약을 맺은 산지 농가의 농산물을 전국 소비자에게 판매하는 단일 브랜드 쇼핑몰이다. 고객은 상품을 구매하기 전에 산지, 농가, 품질 기준, 출고 가능일과 보관법을 확인할 수 있으며, 웹과 모바일 앱에서 주문부터 배송 조회까지 동일한 핵심 경험을 이용한다.

### 2.1 제품 비전

산지와 소비자를 신뢰로 연결해, 누구나 안심하고 좋은 농산물을 구매할 수 있는 대표 농산물 브랜드몰이 된다.

### 2.2 핵심 가치

1. **신뢰성**: 생산자와 산지, 품질 정보를 투명하게 제공한다.
2. **신선함**: 상품별 출고 가능일과 배송 특성을 명확하게 안내한다.
3. **편리함**: 탐색, 결제, 배송 조회, 문의를 간단하게 만든다.
4. **지속 가능성**: 계약 농가의 안정적인 판로와 합리적인 판매 구조를 지원한다.

## 3. 목표와 비목표

### 3.1 MVP 목표

고객이 상품을 발견하고, 산지·품질 정보를 신뢰한 뒤, 결제와 배송 조회까지 완료하는 핵심 구매 흐름을 검증한다.

### 3.2 비목표

- 여러 판매자가 입점하는 오픈마켓 구축
- 해외 배송
- AI 개인화 추천
- 라이브커머스
- 정기배송 자동 결제
- 복잡한 포인트·등급제

## 4. 대상 고객

### 4.1 핵심 고객

- 전국의 일반 소비자
- 온라인으로 신선식품을 구매하려는 고객
- 산지, 생산자, 품질, 배송 정보를 확인하고 구매하려는 고객

### 4.2 고객의 주요 문제

- 온라인 농산물의 산지와 생산자 정보를 신뢰하기 어렵다.
- 수확·선별 시점과 실제 출고 가능일을 알기 어렵다.
- 상품 하자, 배송 중 훼손, 품질 문제 발생 시 보상 기준이 불명확하다.
- 여러 판매채널의 정보를 비교하고 주문·문의하기가 번거롭다.

## 5. 제품 원칙

- 상품 가격보다 먼저 신뢰에 필요한 정보를 제공한다.
- 신선식품 특유의 변동성을 숨기지 않고 사전에 안내한다.
- 웹과 앱에서 핵심 구매 흐름의 정책과 상태를 일관되게 유지한다.
- 운영자가 품절, 출고 지연, 기상 악화에 대응할 수 있게 한다.
- 고객에게 보여주는 정보와 내부 운영 상태를 구분하되, 고객에게 필요한 상태는 투명하게 공개한다.
- 제품명은 **어울몰**을 유지한다. 만석 디자인 시스템의 황금·크림 색상, 서체, 카드 등은 시각 디자인 참고안이며, 진주·의령·함안/부자마을 이야기는 대외 표현의 콘셉트다. 상품 등록 산지를 특정 지역으로 제한하는 시스템 규칙은 두지 않는다. `cyhuh7950/owoolmall`의 정적 화면도 참고 자료일 뿐이며, 실제 화면 시안은 신산님 검토 뒤 확정한다.

## 6. 핵심 고객 여정

`상품 발견 → 산지·품질 확인 → 옵션·수량 선택 → 장바구니 → 배송 옵션 확인 → 결제 → 출고·배송 조회 → 수령 → 리뷰 또는 문의`

### 6.1 구매 성공 시나리오

1. 고객이 홈, 카테고리, 검색 또는 추천 영역에서 상품을 발견한다.
2. 고객이 상품 상세에서 산지, 농가, 품질 기준, 중량·등급, 출고일, 보관법을 확인한다.
3. 고객이 옵션과 수량을 선택해 장바구니에 담는다.
4. 고객이 배송지와 배송비, 출고 예상일을 확인한다.
5. 고객이 결제를 완료한다.
6. 어울몰이 주문 접수, 출고, 배송 상태를 알린다.
7. 고객이 상품을 수령한 뒤 리뷰를 작성하거나 문제를 문의한다.

### 6.2 예외 시나리오

- 결제 실패: 실패 사유를 안내하고 결제 재시도 경로를 제공한다.
- 품절: 장바구니·결제 단계에서 판매 불가 상태를 재검증하고 대체 상품 또는 재입고 알림을 제공한다.
- 출고 지연: 지연 사유와 변경된 예상 출고일을 알린다.
- 배송 중 훼손: 사진 등 증빙을 첨부해 교환·환불을 요청할 수 있게 한다.
- 기상 악화: 출고 중지 또는 일정 변경을 고객에게 공지하고 주문별 후속 조치를 기록한다.

### 6.3 역할별 화면 정보구조 참고안

기존 어울몰 정적 시안의 `/buyer`, `/seller`, `/operator`는 각각 고객, 판매자, 관리자 화면을 검토할 때 볼 수 있는 **참고 예시**다. 새 제품의 URL·정보구조·HTML 재사용을 확정하거나 구속하지 않는다. 계정 역할은 **고객·판매자·관리자 세 가지**이며 농가와 어울몰은 같은 판매자 역할을 사용한다. 판매자별로 담당 상품·발송 주문의 범위를 구분한다. 고객 화면은 상품·장바구니·결제·주문 내역을, 판매자 화면은 담당 상품·재고·주문 업무를, 관리자 화면은 전체 주문·재고·배송·환불·정산·프로모션을 구분한다. ## 7. MVP 기능 요구사항

### 7.0 사용자 역할

- **고객**: 상품을 조회하고 구매·배송 조회·문의·리뷰를 이용한다. 판매자·관리자 설정 권한은 없다.
- **판매자**: 농가와 어울몰이 동일한 판매자 역할·처리 절차를 사용한다. 각 판매자는 자신에게 배정된 상품·주문·재고를 직접 관리하고, 담당 발송 주문의 포장·출고 처리와 운송장 입력을 한다. 농가 판매자의 범위는 자기 농가, 어울몰 판매자의 범위는 어울몰 발송 상품·주문이다. 판매자는 고객 환불의 최종 결정·처리와 농가 정산 완료 처리를 하지 않으며 관리자 권한을 포함하지 않는다. 나머지 세부 업무 범위는 추가 확인한다.
- **관리자**: 쇼핑몰 전체 상품·운영 정책과 초기 상품 옵션·가격·재고를 설정하고 고객 환불을 최종 결정·처리하며 농가 정산 완료를 기록한다. 판매자 설정과 충돌하면 관리자 설정을 우선한다. 실제 담당자가 어울몰 판매자와 동일인이어도 시스템에서는 관리자와 판매자의 권한·승인 절차를 별도로 취급한다.
- 동일인이 어울몰 판매자 권한으로 변경을 요청하고 관리자 권한으로 그 요청을 승인할 수 있다. 요청만으로 자동 승인되지 않으며 요청 행위와 승인 행위를 별도로 실행·기록한다. 각 이력에 사용한 역할, 행위자, 시각, 대상·변경 내용을 남긴다.
- 판매자가 제안한 고객 화면 반영 사항은 관리자 승인 후에만 공개한다. 승인 전에는 고객 화면의 기존 승인 내용을 유지하고, 제안·승인 여부를 구분한다. 예외로 재고 0개·품절에 따른 구매 차단과 판매 불가 표시, 실제 출고 처리·운송장 정보는 관리자 승인을 기다리지 않고 고객 화면에 즉시 반영한다. 판매자의 재판매·품절 해제 요청은 일반적인 관리자 승인 절차를 따른다.
- 역할별 허용 범위와 판매자별 담당 상품·주문 범위는 서버에서 검사한다. 농가 소속 판매자는 자기 농가의 상품·주문만, 어울몰 소속 판매자는 어울몰 발송 상품·주문만 변경할 수 있다.

### 7.1 회원·고객 계정

- 이메일·휴대폰·소셜 로그인 지원
- 배송지 등록·수정·삭제
- 주문 내역과 주문 상세 확인
- 알림 수신 설정
- 회원 탈퇴 및 개인정보 처리 관련 안내

### 7.2 상품 탐색

- 농산물 카테고리별 탐색
- 키워드 검색
- 가격, 산지, 재배 방식, 판매 상태 등 필터
- 상품 정렬: 인기순, 최신순, 가격순, 리뷰순
- 품절·판매 예정·판매 중 상태 표시
- 모바일과 PC에서 동일한 상품 정보 제공

### 7.3 상품 상세

- 상품명, 대표 이미지, 가격, 옵션, 중량·등급 표시
- 상품 사진을 여러 장 등록하고 대표 사진·상세 사진을 구분해 순서를 미리 확인한다. 판매자의 사진·설명 변경은 관리자 승인 전까지 고객 화면에 공개하지 않는다.
- 산지와 생산자·농가 프로필 표시
- 수확·선별·검수 관련 정보 표시
- 출고 가능일, 배송 예상 범위, 배송비 표시
- 보관법과 섭취·사용 권장 안내
- 상품별 품질 기준과 교환·환불 조건 표시
- 리뷰와 고객 문의 표시
- 찜 및 재입고 알림 신청

### 7.4 장바구니·주문·결제

- 옵션·수량 선택
- 장바구니 상품 수정·삭제
- 어울몰 발송 상품과 농가 발송 상품은 장바구니에 함께 담을 수 있다. 결제 단계에서 어울몰 발송 주문과 농가 직접 발송 주문을 나누고, 농가 직접 발송 상품은 농가별로 주문을 다시 나눈다. 하나의 주문에 두 발송 방식 또는 서로 다른 농가의 직접 발송 상품을 혼합하지 않는다. 고객은 나뉜 주문을 한 번에 통합 결제한다.
- 같은 농가에서 직접 발송하는 상품은 하나의 발송 주문으로 묶는다. 어울몰 발송 상품은 농가 직접 발송 주문과 묶지 않는다.
- 품절·가격 변경·판매 상태 변경 재검증
- 배송지 선택 및 신규 입력
- 배송비와 할인·쿠폰 적용 결과 표시
- 통합 결제 할인이 여러 발송 주문에 걸치면 할인 대상 상품의 할인 전 금액 비율로 배분한다. 원 단위 반올림 차이는 결정적인 방식으로 조정해 주문별 배분액의 합이 실제 할인액과 정확히 일치하게 한다. 적용 대상이 제한된 할인은 해당 상품 사이에서만 배분한다.
- 주문 전 최종 금액과 출고 예정일 확인
- 결제 성공·실패 결과 처리
- 주문 완료 화면과 주문번호 제공

### 7.5 주문·배송

- 주문 상태: 결제 대기, 결제 완료, 상품 준비, 출고, 배송 중, 배송 완료, 취소, 교환, 환불
- 주문 취소 가능 조건 안내
- 택배사와 운송장 번호 표시
- 농가·어울몰 판매자는 각자 담당 발송 주문의 포장·출고 처리와 운송장 입력을 한다. 실제 출고 처리와 운송장 정보는 관리자 승인 없이 고객 화면에 즉시 표시한다. 출고 처리 시각·운송장 입력 시각·고객 표시 시각을 기록해 배송 상태와 고객의 취소 가능 안내가 어긋나지 않게 한다.
- 출고 마감시간 이후 접수한 주문은 해당 판매자의 다음 출고 가능일을 안내한다. 판매자가 제안한 출고 마감시간·배송 불가 지역의 변경은 관리자 승인 후 적용한다.
- 출고·운송장 입력 오류 또는 지연 입력은 관리자가 사유와 정정 이력을 남겨 바로잡고, 고객에게 이미 잘못 안내한 배송·취소 상태도 정정해 알린다.
- 배송 추적 링크 또는 배송 상태 표시
- 출고 지연·배송 예외 알림
- 주문·취소·교환·환불의 상태 변경은 허용된 순서와 실행 권한을 검사하고, 처리 역할·담당자·시각·사유·전후 상태를 이력으로 남긴다. 판매자는 담당 주문의 출고 정보를 처리하지만 고객 환불의 최종 결정·실행은 관리자만 한다.
- 상품별 교환·환불 요청 접수

### 7.6 리뷰·문의

- 구매 확정 고객의 리뷰 작성
- 평점, 텍스트, 이미지 리뷰 지원 여부
- 상품 문의 등록 및 답변 확인
- 문의 처리 상태와 답변 이력 관리
- 신고·숨김 등 기본 운영 기능

### 7.7 모바일 앱

- 웹과 동일한 계정·상품·주문 데이터 사용
- 푸시 알림: 주문 상태, 출고, 배송, 품절, 재입고
- 찜 목록 및 재입고 알림
- 앱 내 상품 탐색·구매·배송 조회
- 푸시 권한 미허용 시에도 핵심 정보는 앱과 문자·이메일 정책에 따라 확인 가능

### 7.8 관리자

- 상품 등록·수정·판매 상태 관리
- 농가·산지 정보 관리
- 옵션·가격·재고·품절 관리
- 주문·결제·취소·교환·환불 관리
- 어울몰에서 농가로 지급할 금액의 정산 관리
- 출고일·배송 정보 관리
- 쿠폰·기본 프로모션 관리
- 리뷰·문의·신고 관리
- 고객 및 알림 관리
- 운영자 역할별 접근 권한 관리
- 변경 이력과 주요 처리 이력 기록
- 승인 대기, 결제 실패, 결제 후 미출고·출고 지연, 재고 이상, 미처리 고객 문의·클레임을 담당자가 확인하고 원 주문·상품·처리 이력으로 이동할 수 있는 운영 예외 목록 제공. 별도 실시간 관제 제품 도입을 뜻하지 않는다.

### 7.9 초기 판매·시험 품목

- 고추, 고춧가루, 양파, 마늘, 블루베리를 초기 품목으로 사용한다.
- 각 품목의 옵션·가격·초기 재고는 관리자가 설정한다. 재고관리는 필수 기능이다.
- 농가 직접 발송 상품의 이후 재고는 해당 농가 판매자가, 어울몰 발송 상품의 이후 재고는 어울몰 판매자가 직접 관리한다. 초기 재고는 관리자가 설정한다. 재고 0개·품절은 즉시 구매를 차단하고, 판매자의 재고 증가·품절 해제는 관리자 승인 후 구매에 반영한다.
- 개발·통합시험에는 식별 가능한 가상 옵션·가격·재고를 사용한다. 실제 판매 옵션·가격·초기 수량은 인수테스트 준비 시 관리자가 확인·설정한다.

## 8. 운영 및 품질 정책

### 8.1 농가·상품 운영

- 농가별 계약 상태, 판매 가능 상품, 출고 가능 지역을 관리한다.
- 상품에는 산지, 생산자, 생산·선별 기준, 중량·등급, 보관법을 등록한다.
- 재고와 출고 가능일은 관리자 화면에서 변경할 수 있어야 한다.
- 출고 방식은 품목별로 `농가 직접 발송` 또는 `어울몰 집하 후 발송` 중 하나를 설정한다. 한 주문에 어울몰 발송 상품과 농가 발송 상품을 혼합하지 않는다.
- 농가 생산품을 어울몰이 발송하더라도 출고·재고 담당자와 별도로 원래 생산 농가 및 해당 농가의 정산 근거를 유지한다.
- 판매 중지·품절·출고 지연 상태를 고객 화면에 반영한다.

### 8.2 품질·배송

- 신선식품의 품절, 출고 지연, 기상 악화 가능성을 주문 전에 안내한다.
- 상품 하자, 배송 중 훼손, 오배송을 구분해 접수·처리한다.
- 교환·환불 기준과 증빙 필요 여부를 상품 및 고객센터에서 안내한다.
- 배송비 기본값은 3,000원이며 변경 가능하게 한다. 5만 원 이상 무료배송 조건은 통합 결제 총액이 아니라 나뉜 발송 주문 각각의 **할인 적용 전 상품금액**에 적용한다. 무료배송 기준에 못 미치는 발송 주문마다 기본 배송비를 각각 부과한다. 예: 한 발송 주문의 상품금액이 52,000원이고 할인이 5,000원이면 할인 후 47,000원을 결제하더라도 무료배송이다. 판매자가 자기 담당 발송 범위의 기본 배송비 또는 무료배송 기준 변경을 요청하면 관리자가 승인한 뒤에만 적용하며, 승인 전에는 기존 기준을 유지한다. 출고 마감시간과 배송 불가 지역 변경도 판매자 제안·관리자 승인 절차를 따르고, 설정이 충돌하면 관리자 기준을 우선한다.
- 판매자가 재고를 늘리거나 품절을 해제해 구매를 다시 허용하는 변경은 관리자 승인 후 적용한다. 재고 0개·품절에 따른 구매 차단은 승인 없이 즉시 적용한다.
- 취소·교환·환불 기준의 설정 권한은 관리자와 판매자 간 항목·적용 범위별로 분리한다. 설정이 충돌하면 관리자 기준을 우선한다. 고객 환불의 최종 결정과 실제 처리는 관리자가 담당하며, 기준 설정과 개별 환불 승인·실행은 구분한다. 단순 변심과 품질 문제의 실제 판단 기준은 추가 확인한다.
- 출고 전 적법한 주문 취소는 해당 발송 주문에 실제 결제한 상품금액과 배송비를 모두 환불한다. 통합 결제 안에서 일부 발송 주문만 취소하면 그 발송 주문에 귀속된 결제액을 부분 환불한다. 출고 후 환불은 기존의 상품금액만 환불·배송비 제외 요구를 잠정 유지하되, 취소 사유·배송 상태별 법률·약관 적합성 검토 전에는 일률적인 운영 규칙으로 확정하지 않는다. [전자상거래법 제17조·제18조·제35조](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=282793)를 운영·대외 고지 전에 재검토한다.
- 출고 전 한 발송 주문의 상품 일부만 취소해 남은 상품금액이 무료배송 기준 아래로 내려가더라도 남은 주문에 배송비를 새로 부과하지 않는다. 취소 상품에 배분된 실제 결제 상품금액을 환불한다. 발송 주문 전체가 출고 전에 적법하게 취소되면 실제 결제 배송비까지 환불한다.
- 출고 후 취소·교환·환불은 단순 변심, 상품 하자·품질 문제, 오배송·배송 중 훼손 등 사유별로 구분해 판단하도록 설계한다. 배송비·반송비 부담과 최종 약관 문구는 법률 검토 전 확정하지 않는다.
- 환불 기준은 권한이 있는 관리자가 변경할 수 있게 설계하되 적용 시작 시점과 변경 이력을 남기고, 각 주문에 적용된 기준을 확인할 수 있어야 한다. 기준 변경만으로 기존 주문의 환불 권리를 소급 축소하지 않는다.
- 처리 담당자, 처리 상태, 고객 안내 내용을 기록한다.
- 문의·품질 문제의 접수 시각과 처리 상태를 기록하고 관리자에게 알린다. 개발·시험에는 변경 가능한 임시 응답 기한을 사용하며 실제 고객 응대 기한은 운영 인력·약관 검토 후 확정한다.

### 8.3 개인정보·보안

- 회원가입·주문·배송에 필요한 정보만 수집한다.
- 고객, 판매자, 관리자의 접근 권한을 분리하고 판매자별 담당 상품·주문 범위를 검사한다.
- 결제정보는 직접 저장하지 않고 승인된 결제대행사 정책에 따른다.
- 개인정보 보관·파기·열람·정정 정책을 별도 문서와 화면에 반영한다.
- 운영자 주요 행동은 감사 로그로 남긴다.
- 로그인·주문·결제 등 민감한 요청의 반복 시도를 제한하고, 다른 판매자·고객의 자료를 식별자 변경만으로 조회·수정할 수 없도록 서버에서 권한을 검사한다.
- 고객 입력·상품 설명의 스크립트 삽입과 요청 위조를 방어한다. 상품·증빙 이미지 업로드는 파일 형식과 크기를 검사하고, 허용되지 않은 파일을 공개하지 않는다. 구체적 제한값과 악성 파일 검사 방식은 상세 설계에서 정한다.

### 8.4 농가 정산

- 어울몰이 농가 정산에 필요한 주문·취소·환불 금액을 집계·확인·관리할 수 있는 정산 모듈을 MVP에 포함한다. 농가별 최종 지급액을 자동 계산하는 규칙은 현재 업무범위가 아니다.
- 고객 환불은 어울몰이 결정·처리하고, 그 결과를 해당 농가와의 정산 내역에 반영한다. 농가가 고객에게 직접 환불하거나 고객 결제금을 직접 정산받는 흐름은 현재 요구 범위가 아니다.
- 정산 대상 농가, 대상 주문, 산정 근거, 조정·확정 내역과 변경 이력을 확인할 수 있어야 한다.
- 농가별 정산 자료에서 매출과 수수료·배송비·할인·환불액은 각 금액이 실제 발생한 시점을 구분해 기록·정리한다. 발생 시점을 기준으로 일자별로 조회하고, 관리자가 시작일·종료일을 선택한 기간의 항목별 전체 금액을 합산한다. 월 단위로 고정하지 않는다. 완료된 기간 이후 발생한 환불도 실제 환불 발생 시점의 자료에 기록하며 과거 완료 기간으로 소급하지 않는다. 환불 자료에는 원래 판매한 주문·상품과 판매 시점을 근거로 연결한다. 예: 5월 1일 판매 → 5월 20일 정산 완료 → 7월 1일 환불이라면, 7월 1일 환불로 기록하고 5월 1일 판매 상품·주문을 근거로 표시한다. 각 항목의 농가·어울몰 부담과 가산·차감 판단은 초기에는 오프라인 업무이며 시스템에서 자동 결정하지 않는다.
- 초기 운영 단계에서 어울몰 시스템은 농가별 선택 기간 집계와 근거 등 실제 송금에 필요한 자료를 준비한다. 최종 지급액의 오프라인 결정과 실제 송금은 시스템 밖에서 수행하며, 관리자 역할의 담당자만 선택 기간에 대해 **농가별로 정산 완료 여부를 개별 기록**한다. 한 농가의 완료 표시는 다른 농가의 상태를 바꾸지 않는다. 완료 표시를 받으면 시스템은 해당 농가·기간의 정산을 완료 상태로 처리한다. 동일 농가의 완료된 정산 기간과 겹치는 기간은 중복 정산 완료할 수 없으며, 완료 기간 뒤 발생한 환불은 발생일이 속한 새 기간에 기록한다. 판매자 역할은 정산 완료를 처리할 수 없다. 자동 송금이나 계좌이체 상세정보 관리는 초기 개발 범위에서 제외한다.
- PG가 어울몰에 지급하는 정산과 어울몰이 농가에 지급하는 정산은 별개다.

## 9. 비기능 요구사항

- 모바일 우선 반응형 UI를 제공하고 주요 화면은 PC에서도 사용 가능해야 한다.
- 핵심 상품 탐색 화면은 일반적인 모바일 네트워크 환경에서 빠르게 표시되어야 한다.
- 주문·결제 요청은 중복 제출로 중복 주문이 발생하지 않아야 한다.
- 가격·재고·판매 상태는 장바구니 및 결제 직전에 재검증한다.
- 장애 또는 외부 배송·결제 연동 실패 시 고객에게 재시도 또는 문의 경로를 제공한다.
- 운영자가 주요 주문 상태 변경과 품질 이슈를 추적할 수 있어야 한다.
- 운영자는 실패 결제, 미출고·지연 주문, 미처리 승인·문의·클레임을 확인하고 처리 이력까지 추적할 수 있어야 한다.
- 웹과 앱의 주문 상태, 가격, 재고 표시가 불일치하지 않아야 한다.

## 10. 성공 지표

### 10.1 핵심 지표

- 상품 상세 조회 대비 구매 전환율
- 결제 완료율 및 결제 실패율
- 주문 후 취소·환불·교환율
- 정시 출고율
- 배송 중 훼손·품질 불만 비율
- 리뷰 작성률 및 평균 평점
- 첫 구매 고객의 60일 내 재구매율
- 고객 문의 최초 응답 시간
- 농가별 판매량·품절률·정산 처리 시간

### 10.2 초기 목표 기준

- 주문 결제 성공률 95% 이상
- 정시 출고율 95% 이상
- 배송·품질 관련 클레임률 3% 이하
- 첫 구매 고객의 60일 내 재구매율 20% 이상
- 핵심 구매 흐름의 치명적 오류 0건

초기 목표 수치는 실제 상품군, 평균 주문금액, 배송권역, 농가 수, 판매 기간을 확인한 뒤 조정한다.

## 12. 주요 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|

| 신선식품 배송 중 훼손 | 비용 증가, 신뢰 하락 | 포장 기준, 증빙 접수, 처리 SLA |
| 웹·앱 기능 불일치 | 고객 혼란 | 공통 API·정책, 핵심 시나리오 통합 테스트 |
| 초기 판매량 부족 | 농가·운영 효율 저하 | 대표 상품 중심 출시, 재구매와 후기 확보 |

## 13. 출시 전 필수 검증

- 상품 탐색부터 결제 완료까지 웹 핵심 구매 시나리오
- 앱 핵심 구매 시나리오와 푸시 알림
- 품절·가격 변경·출고 지연·결제 실패 예외 처리
- 주문 취소·교환·환불 처리
- 출고 전 적법한 취소에서 해당 발송 주문의 상품금액과 실제 결제 배송비가 모두 환불되는지, 통합 결제의 다른 발송 주문은 유지되는지 검증
- 출고 전 상품 일부 취소로 무료배송 기준 아래로 내려가도 배송비가 새로 부과되지 않고 취소 상품의 실제 결제금액만 환불되는지 검증
- 여러 발송 주문에 적용된 할인액 배분 합계가 통합 결제 할인액과 원 단위까지 일치하는지 검증
- 배송 추적 및 고객 알림
- 운영자 상품·재고·주문 상태 변경
- 농가별 정산 항목 합계와 주문·취소·환불 반영 내역 대조(최종 지급액 자동 계산 여부를 검증한다는 뜻은 아님)
- 완료된 과거 정산 뒤 환불이 발생하면 환불 발생일에 기록되고 원래 판매 주문·상품을 추적할 수 있는지 검증
- 동일 농가의 완료된 기간과 겹치는 기간을 중복 완료할 수 없고 다른 농가의 기간은 독립적으로 처리되는지 검증
- 농가 생산품을 어울몰이 발송할 때 어울몰의 출고·재고 담당과 원래 생산 농가의 정산 근거가 모두 유지되는지 검증
- 관리자가 임의의 시작일·종료일을 선택해 농가별 매출·수수료·배송비·할인·환불액을 조회하고, 농가별 정산 완료 여부를 개별 기록할 수 있는지 검증. 한 농가의 완료 표시가 같은 기간 다른 농가의 상태를 바꾸지 않아야 함
- 개인정보·권한·운영자 접근 검증
- 고객·판매자·관리자별 식별자 변조 접근, 로그인/주문 반복 요청, 스크립트 삽입·요청 위조, 허용되지 않은 이미지 업로드 차단 검증
- 주문·클레임의 상태 변경 순서와 처리 권한·사유 이력이 유지되는지, 상품 사진 순서·대표 사진 미리보기와 승인 전 공개 차단이 동작하는지 검증
- 실제 배포 후보의 정확한 버전으로 백업 복원·이전 버전 복귀·핵심 구매 흐름 재확인을 시험하고, 운영자가 재현할 수 있는 절차를 문서화한다. WSL 개발·통합시험 결과와 Oracle 인수환경 검증 결과는 구분한다.
- 모바일 주요 화면 접근성·가독성·성능
- 실제 배송 정책과 화면 안내의 일치 여부
- 발송 주문별 할인 적용 전 상품금액으로 5만 원 무료배송을 판정하고, 할인으로 결제금액이 5만 원 미만이 되어도 배송비를 부과하지 않는지 검증
- 판매자의 기본 배송비·무료배송 기준 변경 요청은 관리자 승인 전까지 적용되지 않고, 승인 후 자기 담당 발송 주문에만 적용되는지 검증
- 농가·어울몰 판매자의 일반 고객 화면 반영 제안은 관리자 승인 전에는 공개되지 않고, 승인 후에만 공개되는지 검증(품절·재고 0개 및 실제 출고·운송장 정보는 즉시 반영 예외)
- 재고 0개 또는 품절 시 관리자 승인 전에도 상품·옵션 구매가 즉시 차단되고, 장바구니·결제 단계의 재검증에서 추가 주문이 성립하지 않는지 검증
- 재고 증가·품절 해제는 관리자 승인 전 구매 가능 상태로 바뀌지 않는지 검증
- 어울몰 판매자가 어울몰 발송 상품 재고만 직접 관리하고 농가 직접 발송 상품 재고는 변경할 수 없는지 검증
- 농가·어울몰 판매자가 각각 담당 발송 주문의 포장·출고·운송장을 입력하면 관리자 승인 대기 없이 실제 출고 상태·운송장이 고객 화면에 표시되는지 검증
- 출고 마감시간 이후 주문의 다음 출고 가능일 안내와 출고·운송장 오입력의 관리자 이력 정정·고객 안내를 검증
- 동일인이 어울몰 판매자와 관리자 업무를 맡더라도 판매자 권한으로 농가 정산 완료나 고객 환불 최종 결정을 실행할 수 없는지 검증
- 동일인이 어울몰 판매자 권한으로 낸 요청을 관리자 권한으로 승인할 수 있지만 요청 단계에는 고객 화면이 바뀌지 않고, 요청·승인의 역할·행위자·시각·대상 이력이 각각 남는지 검증

## 14. 미결정 사항

- 초기 품목은 고추·고춧가루·양파·마늘·블루베리로 지정됨. 개발·시험 값은 가상 자료로 준비하고 실제 옵션값·판매 가격·초기 수량과 카테고리 분류는 인수테스트 준비 시 확인
- 평균 주문금액과 가격 정책
- 배송사·실제 포장 방식은 인수테스트 준비 시 확인(무료배송은 발송 주문별 할인 적용 전 상품금액 기준으로 확정)
- 통합 결제의 부분 취소·환불은 위 원칙대로 설계하되 PG 실제 부분 환불 기술 검증은 인수테스트 준비 시 수행. 출고 후 사유별 배송비·반송비와 약관은 법률 검토 전 확정하지 않음
- 판매자·관리자의 나머지 세부 화면·편집 항목은 상세 설계에서 구체화. 판매자 일반 제안의 공개 전 승인, 재고 0개·품절 시 즉시 차단, 재고 증가·품절 해제 승인, 출고·운송장 즉시 공개, 판매자별 담당 범위, 관리자 우선은 확정
- 농가 정산은 관리자가 시작일·종료일을 선택하고 농가별 개별 완료. 동일 농가 완료 기간 중복은 금지. 수수료 구조와 배송비/할인/환불액의 부담 판단 및 최종 지급액 결정은 초기 시스템 업무범위 밖
- 결제대행사와 지원 결제수단
- 회원가입 방식과 소셜 로그인 제공 범위
- 취소·교환·환불의 출고 후 사유별 법률·약관 판단 기준과 실제 고객 응대 기한(시험 중에는 변경 가능한 임시 기한 사용)
- 현행 설계에 맞춘 임시 화면의 신산님 검토·확정 결과(기존 시안은 참고만 사용). 인수테스트 핵심 시나리오는 분할 주문·통합 결제, 발송 주문별 무료배송, 재고 차단, 판매자 요청/관리자 승인, 취소·환불, 농가별 정산으로 지정
- 앱 출시 플랫폼 및 푸시 메시지 운영 정책
- 개인정보 보관 기간과 법률 검토 결과

## 15. 완료 조건

MVP는 고객이 상품 정보와 출고 조건을 확인하고 정상적으로 결제한 뒤 배송 상태를 조회할 수 있어야 한다. 운영자는 상품·농가·재고·주문·배송·품질 이슈를 관리할 수 있어야 하며, 품절·지연·훼손과 같은 주요 예외 흐름을 고객에게 안내하고 처리할 수 있어야 한다.
