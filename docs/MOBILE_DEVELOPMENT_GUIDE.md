# 고객 앱 개발 확인 안내

현재 상태는 S7 진행 중이다. 실제 메일·HTTPS·PG·푸시 인수 또는 APK 검증 완료가 아니다.

## 연결 설정

- 기존 서버의 공개 API 주소를 `EXPO_PUBLIC_API_ORIGIN`에 지정한다.
- 서버가 허용한 웹 Origin을 `EXPO_PUBLIC_WEB_ORIGIN`에 지정한다. 예: 현재 WSL 개발 서버는 `http://172.27.253.53:9091`이다. 인증·Origin 검사를 완화하지 않는다.
- 두 공개 설정에는 비밀번호·토큰·DB URL을 넣지 않는다. 세션은 기존 HttpOnly cookie 경로를 사용하며 실제 네이티브 cookie 왕복은 에뮬레이터에서 추가 확인해야 한다.
- `EXPO_PUBLIC_ENABLE_MOCK_PAYMENT=1`은 모의 버튼 표시 설정일 뿐 서버 권한이 아니다. 서버가 기존 loopback/development mock 경계를 허용한 격리 환경에서만 실제 모의 요청이 처리된다. 현재 공개 WSL 개발 실행은 PAYMENT_MODE=disabled이므로 이 설정으로 결제를 활성화할 수 없다.

## 구현된 화면 확인 순서

1. 상품 화면에서 상품명/판매자를 검색하고 상세·옵션·가격·품절과 사진을 확인한다. 목록은 서버의 최신순·숫자 페이지 계약을 따른다.
2. 구매자 계정으로 로그인한다. 서버의 고객 세션 확인 이후에만 장바구니·배송지·본인 주문·문의로 이동한다.
3. 상세에서 수량과 옵션을 정해 담고 장바구니에서 변경/제거한다. 금액·배송 구분은 서버 견적을 표시한다.
4. 배송지·알림 화면에서 배송지를 저장한다. 실제 개인정보 대신 식별되는 시험 자료만 사용한다.
5. 장바구니에서 재고 예약→배송지 선택→필요 시 상품 쿠폰 코드 입력/혜택 재견적→서버 확인 금액으로 주문을 생성한다. 예약 중 수량 변경은 막고 먼저 해제한다.
6. 격리 loopback mock 서버에서만 모의 거절·지연·승인을 확인한다. 응답 유실은 같은 입력·같은 버튼으로 재확인하며 성공을 추측하지 않는다. 실제 PG가 아니다.
7. 주문·배송에서 본인 결제 완료 목록과 본인 주문 번호를 조회한다. 출고 상태·예상일·택배사·운송장/지연 안내는 서버 결과를 표시한다.
8. 상세에서 상품 문의를 접수하고 내 문의에서 답변을 조회한다. 수신 설정은 서버에 저장하지만 실제 발송·OS 푸시 수신을 뜻하지 않는다. 기기 푸시 권한은 미구현/별도 승인 경계이며 주문·내 문의 조회가 대체 경로다.
9. 로그아웃·세션 만료 때 장바구니·배송지·주문·문의 상태가 화면에서 제거되고 재로그인이 필요한지 확인한다.

현재 지속 WSL QA 계정은 이전 정리의 disabled 상태를 유지한다. 위 계정 흐름은 폐기 격리 DB의 책임자 준비 시험 계정으로 실행하며 기존 지속 계정을 임의 활성화하지 않는다.

## 검증 범위와 남은 일

- 로컬 실제 React/HTTP 경계 시험과 WSL 실제 HTTP/DB 경로를 분리 기록한다. 테스트용 네이티브 컨트롤 대체는 에뮬레이터 실행 증거가 아니다.
- Android JS/Hermes export는 APK·네이티브 설치·승인 아이콘·실기기 결과가 아니다.
- OS 푸시 권한/거부 및 모의 공급자 복귀, 장바구니 혜택 전체 선택, 환불/리뷰/찜 등 설계 전체 모바일 대응의 누락을 별도 상태로 검토한다. 아직 전체 S7 또는 S8 완료라고 하지 않는다.
- 정식 관리자 초기 설정, OS PDF 저장·열기, 역할별 전체 연결·매뉴얼 리허설은 `design_change.md`의 잔여 조건을 따른다.
