# 고객 앱 개발 확인 안내

현재 상태는 S7 진행 중이다. Android 개발 APK 설치·핵심 화면·모의 구매·기기 내 모의 알림은 확인했다. 배포용 release·실기기·실제 메일/HTTPS/PG/원격 푸시 인수 완료는 아니다. 기능별 근거와 정확한 APK/JS commit은 `WORK_STATUS.md`를 따른다.

## 연결 설정

- 기존 서버의 공개 API 주소를 `EXPO_PUBLIC_API_ORIGIN`에 지정한다.
- 서버가 허용한 웹 Origin을 `EXPO_PUBLIC_WEB_ORIGIN`에 지정한다. 예: 현재 WSL 개발 서버는 `http://172.27.253.53:9091`이다. 인증·Origin 검사를 완화하지 않는다.
- 두 공개 설정에는 비밀번호·토큰·DB URL을 넣지 않는다. 세션은 기존 HttpOnly cookie 경로를 사용한다. Android에서 로그인·재시작 후 세션 복원·본인 조회·로그아웃을 확인했으며 새 인증정보 저장 수단은 추가하지 않았다.
- `EXPO_PUBLIC_ENABLE_MOCK_PAYMENT=1`은 모의 버튼 표시 설정일 뿐 서버 권한이 아니다. 서버가 기존 loopback/development mock 경계를 허용한 격리 환경에서만 실제 모의 요청이 처리된다. 현재 공개 WSL 개발 실행은 PAYMENT_MODE=disabled이므로 이 설정으로 결제를 활성화할 수 없다.
- `EXPO_PUBLIC_ENABLE_MOCK_NOTIFICATIONS=1`과 개발 빌드가 함께 있을 때만 개인정보 없는 기기 내 모의 알림 버튼이 보인다. 서버 주문 사건의 원격 푸시가 아니며 토큰 발급·기기등록·외부 전송은 구현하지 않았다. 이 설정은 권한을 자동 요청하지 않는다.
- 현재 보존 APK는 x86_64 debug 개발판으로 실행할 때 해당 commit의 Metro가 필요하다. 일반 Android 휴대폰에 바로 설치하는 release 배포판으로 안내하지 않는다. 새 native SDK/config 변경 후에는 이전 APK에 JS만 갱신해서 native 검증을 대신하지 않는다.

## 구현된 화면 확인 순서

1. 홈의 공개 메뉴/기획전/추천과 상품 상세를 확인한다. 상품 화면에서는 상품명/판매자, 상품 분류·농가, 최신순/낮은 가격순/높은 가격순을 선택한 뒤 검색한다. 적용 조건을 바꾸면 첫 페이지부터 조회하고 추가 페이지는 기존 적용 조건을 유지한다.
2. 구매자 계정으로 로그인한다. 서버의 고객 세션 확인 이후에만 장바구니·배송지·본인 주문·문의로 이동한다.
3. 상세에서 수량과 옵션을 정해 담고 장바구니에서 변경/제거한다. 금액·배송 구분은 서버 견적을 표시한다.
4. 배송지·알림 화면에서 배송지를 저장한다. 실제 개인정보 대신 식별되는 시험 자료만 사용한다.
5. 장바구니에서 재고 예약→배송지 선택→보유 상품 쿠폰/코드와 발송별 배송비 혜택 선택·재견적→서버 확인 금액으로 주문을 생성한다. 예약 중 수량 변경은 막고 먼저 해제한다. 재시작 뒤 장바구니와 활성 예약은 서버에서 다시 읽는다.
6. 격리 loopback mock 서버에서만 모의 거절·지연·승인을 확인한다. 응답 유실은 같은 입력·같은 버튼으로 재확인하며 성공을 추측하지 않는다. 실제 PG가 아니다.
7. 주문·배송에서 본인 결제 완료 목록과 본인 주문 번호를 조회한다. 출고 상태·예상일·택배사·운송장/지연 안내는 서버 결과를 표시한다.
8. 상세에서 상품 문의를 접수하고 내 문의에서 답변을 조회한다. 찜·옵션별 재입고 신청은 찜·재입고에서 관리한다. 재입고 신청/처리는 실제 외부 수신의 증거가 아니다.
9. 주문 상세에서 출고 전 취소·환불 요청, 구매확정·리뷰/이미지·클레임/증빙을 서버 상태가 허용하는 경우 처리한다. 요청 접수는 환불 완료/관리자 결정이 아니며 실제 결과는 재조회한다.
10. 배송지·알림의 Android 알림 권한 요청 버튼을 눌러 OS 허용/거부를 선택한다. 거부 시 모의 발송은 차단되고 주문·내 문의에서 직접 확인할 수 있다. OS 설정에서 바꿨다면 기기 알림 상태 다시 확인을 누른다. 개발용 모의 알림 보내기→Android 알림창 표시→모의 알림 지우기는 이 앱의 시험 알림만 제거한다. 서버 수신 동의 설정은 별개이며 자동으로 저장하거나 허용하지 않는다.
11. 로그인 화면의 가입하기/비밀번호 찾기는 서버 접수 경로다. 실제 메일/HTTPS 확인은 인수 보류이고, 탈퇴 요청은 명시 안내 확인 후 접수하며 즉시 계정 삭제가 아니다.
12. 로그아웃·세션 만료 때 장바구니·배송지·주문·문의 상태가 화면에서 제거되고 재로그인이 필요한지 확인한다.

현재 지속 WSL QA 계정은 이전 정리의 disabled 상태를 유지한다. 위 계정 흐름은 폐기 격리 DB의 책임자 준비 시험 계정으로 실행하며 기존 지속 계정을 임의 활성화하지 않는다.

## 검증 범위와 남은 일

- 로컬 실제 React/HTTP 경계 시험과 WSL 실제 HTTP/DB 경로를 분리 기록한다. 테스트용 네이티브 컨트롤 대체는 에뮬레이터 실행 증거가 아니다.
- Android JS/Hermes export는 APK·네이티브 설치·승인 아이콘·실기기 결과가 아니다.
- 개발 전용 카카오 mock은 승인된 폐기 DB의 가상 고객만 접속한다. Android에서는 `__DEV__`와 `EXPO_PUBLIC_ENABLE_KAKAO_MOCK=1`, Web에서는 개발 빌드와 `NEXT_PUBLIC_ENABLE_KAKAO_MOCK=1`이 모두 필요하다. 서버 기본값은 `KAKAO_AUTH_MODE=disabled`이며 실제 DB 식별·서명된 QA manifest·양쪽 루프백을 확인한 mock 서버만 허용한다. 정식 WSL 공개 개발 주소에서 켤 수 있는 기능이 아니다.
- 격리 API/Web의 `127.0.0.1:9092`/`127.0.0.1:9091`을 에뮬레이터에 reverse 연결한 뒤 로그인 화면의 **카카오 모의 로그인**을 누른다. Chrome의 가상 고객 화면에서 **모의 승인**을 선택하면 앱의 기존 고객 세션 확인 후 본인 배송지 조회가 가능하다. 실제 Android 승인→scheme 복귀→고객 주소와 취소/실패·cold start 무발급을 확인했다. 취소/실패 안내 후 앱의 **모의 로그인 취소**로 대기를 닫고 다시 시작할 수 있다. 앱 강제 종료·브라우저 재로드로 증명이 없어지면 새로 시작하며 복귀 링크만으로 로그인하지 않는다.
- 실제 카카오 공급자 연결·계정 연결/가입·실기기 인수는 미구현 또는 별도 미확인이다. 이 개발 mock의 PASS를 실제 카카오 로그인으로 표시하지 않는다. 정확한 실행 commit·APK/JS 구분·시험 및 정리 근거는 WORK_STATUS를 따른다.
- 기존 모의 결제는 서버 API의 승인/거절/지연·멱등 경계이며 외부 PG SDK/브라우저 복귀는 미구현이다. 로컬 알림은 원격 기기등록/푸시 공급자 adapter를 대신하지 않는다. 이 누락과 실제 공급자 인수 미검증을 구분하며 전체 S7 또는 S8 완료라고 하지 않는다.
- 정식 관리자 초기 설정, OS PDF 저장·열기, 역할별 전체 연결·매뉴얼 리허설은 `design_change.md`의 잔여 조건을 따른다.
